# チャンネルとモデル

## チャンネルの設定を行う

Chat内でモデル選択機能を開き、チャンネル管理を選択します。**チャンネルを追加**を選択し、接続タイプを選び、必要な情報を入力して保存してください。新しいチャットのために、そのチャンネルからモデルを選択します。カスタムのAgentの場合は、Agentの設定でチャンネルとモデルを選択します。

チャンネルは個人のチャット設定ではなく、Controllerが管理しています。認証された環境では、チャンネル管理には`admin:config`スコープが必要です。管理者は、APIキーをチャットユーザーに配布することなく、共有チャンネルを設定できます。

![実際のチャンネル設定ダイアログでモデルチャンネルを追加する方法](../assets/chat/channel-settings.png)

通常のAPIチャンネルには、名前、プロバイダープロトコル、基本URL、認証情報、そしてモデル識別子といった要素があります。選択したエンドポイント用に発行されたAPIキーを使用してください。LSMアカウントのパスワードではなく、APIキーを使用してください。LSMはControllerからリクエストを送信しますが、ラップトップで正常に動作するURLが、Controllerからは正しく動作しない場合があります。

| プロトコル | 例としてのAPI基本URL | 使用法 |
|---|---|---|
| OpenAI Chat Completions | `https://api.openai.com/v1` | OpenAI対応のチャットゲートウェイやローカル推論サーバー |
| OpenAI Responses | `https://api.openai.com/v1` | Responses APIを提供するゲートウェイ |
| 人類原住民 | `https://api.anthropic.com/v1` | アンタルクティックなメッセージに対応したAPI |
| Google Gemini ネイティブ | `https://generativelanguage.googleapis.com/v1beta` | Gemini generateContentに対応したAPI |

プロバイダーが要求する基本URLを使用する必要があります。例えば、`/chat/completions`で終わるURLのような完全な生成リクエストURLを直接使用するのではなく、その基本URLを使用してください。OpenAIとの互換性を主張しているゲートウェイであっても、Chat Completionsはサポートされているかもしれませんが、Responseやツールの呼び出し、ストリーミング処理、多モダル入力や推論機能についてはサポートされていない場合があります。実際にサポートされているプロトコルを選択してください。例えば、URLはプロトコルの例であり、無料でアクセスできることを保証するものではありません。

## ローカルおよびカスタムエンドポイント

OpenAIと互換性のあるサーバーで、Controller自体がそのサーバーとして機能している場合、基本URLは`http://127.0.0.1:8080/v1`になるかもしれません。Docker内で実行する場合、loopbackとは、物理的なホストを指すのではなく、そのコンテナを指します。Controllerのネットワーク名前空間からアクセス可能なアドレスを使用してください。単にリモートワーカーの登録を行っただけでは、その推論APIにアクセスすることはできません。

モデルのURLバリアントにはHTTPSが必要です。ただし、`localhost`、`127.0.0.1`、`::1`などのローカルアドレスでのHTTPエンドポイントは例外です。LANアドレスやDockerサービス名で構成されるHTTPエンドポイントは、HTTPSゲートウェイを通じてのみ公開される必要があります。ホストされたChatプライベートエンドポイントの使用はできません。基本URLには、埋め込まれた認証情報やフラグメント、クエリ文字列などを含めてはいけません。

リモートエンドポイントではTLSを使用し、信頼できるプライベートゲートウェイへのアクセスを制限してください。また、推論サーバーに対してモデル識別子を確認する必要があります。APIキーは、プロンプトやスクリーンショット、クエリ文字列、公開されている設定などに記載してはいけません。既存のチャンネルを編集する際には、APIキーを空欄にしておくことで、保存されているキーを保持できます。サービスがサポートしている場合にのみ、無キー接続を使用してください。

## 環境によって設定されるデフォルト値

内蔵されているOpenAIプロフィールは、`LOCAL_SHELL_MCP_MODEL_BASE_URL`（または`OPENAI_BASE_URL`）、`LOCAL_SHELL_MCP_MODEL`、および`LOCAL_SHELL_MCP_MODEL_API_KEY`（または`OPENAI_API_KEY`）を使用して起動前に設定できます。内蔵されているAnthropicやGoogleのプロフィールでは、`ANTHROPIC_API_KEY`と`GOOGLE_KEY`/`GOOGLE_API_KEY`がそれぞれ利用されます。保存された内蔵プロフィールは、環境によって生成されるフォールバックよりも優先されます。複数の独立したエンドポイントを使用する場合は、名前付きチャンネルを利用してください。環境で設定されたデフォルト値は、サービスの秘密情報を保護する手段としては適していません。

## ChatGPTアカウントの認証/承認

このアカウント/コーデックスチャンネルでは、通常のAPIキーではなく、ChatGPTのアカウント認証プロセスを使用しています。チャンネル管理から認証を行い、公式の認証ページにログインしてください。ローカル環境でのデプロイでは、コールバックが自動的に実行されます。もしブラウザがループバックリスナーに接続できない場合は、コールバックURLをブラウザのアドレスバーからコピーして、認証ダイアログに貼り付けてください。この手動の認証プロセスでは、ループバックアドレスでの接続エラーが発生する可能性があります。

コールバック URL は認証情報として扱い、チャットに送信したり公開したりしないでください。Controller は認可情報をサーバー側に保存し、可能な場合は認証情報を更新します。アカウントの有効期限が切れたりアクセスが取り消されたりした場合は再認可してください。利用可能なモデル、プランの制限、許可される利用方法は上流のアカウントサービスが決定します。LSM は追加のサブスクリプション枠を提供しません。

## モデルの発見とコンテキストの制約

自動検出機能を有効にして、プロバイダーからモデル情報を取得します。Controllerは定期的に（現在は10分ごとに）その情報を更新します。手動で更新することも可能です。検出に失敗した場合でも、以前保存されていたモデルデータは保持されます。もしプロバイダーが対応するモデルリストエンドポイントを持っていない場合は、自動検出機能を無効にし、各行に1つのモデル識別子を手動で入力してください。

モデル検出は、OpenCode Go/Zen のネストされた `limit.context`、OpenRouter の `context_length`、vLLM の `max_model_len`、Gemini の `inputTokenLimit` など、明示的なコンテキストウィンドウのメタデータを認識します。最大入力長のみが報告された場合は代替値として使用します。出力上限やモデル名からコンテキスト容量は判断しません。どちらも報告されない場合は不明のままです。

各モデルのコンテキストウィンドウを、そのモデルが存在する文脈に応じて指定します。個々のモデルに対して明示的な値を設定することで、既に確認されているメタデータを上書きしたり、不足している値を補完することができます。エディターでは、1から2,000,000トークンまでのデータを受け入れられます。これは設定範囲であり、必ずしも特定のプロバイダーがその容量をサポートしているとは限りません。サーバー側の設定や、モデル自体の制限を考慮して、適切な上限値を使用してください。

認識された公式プロバイダーのエンドポイントでは、プロバイダー ID とモデル ID の完全一致により、公開カタログ models.dev から不足するコンテキスト値を補完できます。プロバイダーのメタデータがこの代替値より優先され、手動設定は両方に優先します。Controller は6時間の共有インメモリカタログキャッシュを使用し、取得に失敗した場合は最後の正常なキャッシュを維持して10分後に再試行します。チャネルの認証情報、URL、モデル ID は models.dev に送信されません。不明なエンドポイントや一致しない ID については、プロバイダーが上限を報告しない限り不明のままです。

## サンプリング、推論、そしてその利用方法

チャンネル/モデルのデフォルト設定によって、選択されたプロバイダがサポートするリクエストパラメータが決まります。チャットコンポーザーでは、利用可能な情報を提供することがあります。さまざまなプロトコルでは、サンプリングや推論の方法が異なります。あるオプションが特定のモデルではサポートされていない場合もあります。まずはプロバイダのデフォルト設定から始めて、一つずつ設定を変更していきます。

LSMは、正確なストリーミングトークンの使用量を要求することができます。また、プロバイダがその使用オプションを拒否した場合には、代替手段を採用します。使用状況を返さないエンドポイントでは、正確な請求やキャッシュ統計を提供することはできません。[メモリとコンテキスト](context.md)を参照してください。そこで、累積的な消費量と現在のコンテキスト容量との違いが説明されています。

## チャンネルの変更や削除

会話は、選択されたモデルやエージェント、およびその履歴を保持します。エンドポイントを変更する際や、プロバイダーの問題をデバッグする際には、意図的にモデルを切り替える必要があります。使用中のチャンネルを名前変更することは、参照を保護するために制限されています。使用中のチャンネルを削除する場合は、追加の確認が必要です。履歴は残りますが、削除されたチャンネルを参照しているエージェントやチャットは、再び使用可能な代替手段を選択する必要があります。

チャンネルの設定はサーバー側で管理されており、ブラウザ上でのプリセットではありません。認証情報は、通常のチャンネルカタログの応答によって返されません。Controllerの状態ディレクトリやバックアップを、認証情報を持つデータとして保護してください。

## 接続のチェックリスト

1. ControllerがAPIホストに接続できるか、およびTLSが正しく機能しているかを確認してください。
2. 基本パス、プロトコル、認証情報、そして正確なモデルIDを確認してください。
3. ディスカバリーを更新するか、手動で既知のモデルを入力してください。
4. 短いプレースホームテキストを送信し、その後、小規模なツール呼び出しを試してみてください。
5. エラーの詳細を確認してください。上流のHTTPステータス、タイムアウト、またはサポートされていないオプションに関するエラーが発生しているかどうかを確認してください。無効な認証情報を繰り返し試行しないでください。

[管理とトラブルシューティング](administration.md)を参照してください。そこでは、レート制限の処理、ストリーミングの中断、および認証エラーの処理について説明されています。
