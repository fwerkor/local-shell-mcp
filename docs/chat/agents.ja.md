# エージェントとスキル

## いつエージェントを作成するべきか

直接モデルチャットは、一度だけ使用する質問やタスクに適しています。エージェントとは、何度も選択可能な保存された設定のことです。エージェントは、スケジュールされたチャットで使用されることも、他のエージェントに委託されることもあります。異なるエージェントは、異なるチャンネル、モデル、指示、アクセスポリシーを使用することがあります。ただし、すべてのエージェントが同じコントローラーを共有しているわけではなく、必ずしも同じメモリ範囲やツールを持っているわけではありません。

## エージェントの設定を行う

WebUIからエージェントの管理を行います。エージェントを作成し、識別可能な名前を付け、そのモデルを選択します。また、タスクの説明、期待される出力結果、制約条件、検証要件などを記述します。必要な機能を設定した後、保存して、新しい会話を開始します。

![エージェントビルダーで、指示、ツール、承認、スキルの設定が表示されている図](../assets/chat/agent-builder.png)

例えば、リポジトリのレビュアーには、以下のような指示があるかもしれません。

```text
現在のメインブランチと比較して、変更点を確認してください。
結論を出す前に、リポジトリやテスト結果を確認してください。
ファイルを編集したり、コミットを行ったり、何かをデプロイしたりしないでください。
具体的な発見点を報告し、その際にはパスや証拠も記載してください。
```

指示は、行動を導くために役立ちますが、権限の範囲を示すものではありません。マシンのアクセス権を「読み取り専用」に設定し、審査者が何も変更しない場合は、不要な外部のMCP機能を省略してください。 [ツールと権限](permissions.md).

コードレビュー、実装、運用といった異なる役割を持つ場合は、それぞれ別のエージェントを使用することが望ましいです。各エージェントには、できるだけ少ない権限を与え、その役割に適したモデルを用意しましょう。エージェントが起動できない場合は、参照されているチャンネルやモデルを確認した上で、関連しない設定を変更してください。

## Skills

スキルパッケージには、再利用可能な指示や関連ファイルが含まれており、通常は`SKILL.md`というファイルとして保存されます。スキルをWebUIで管理し、必要なスキルを有効にして、エージェントやチャットユーザーが利用できるようにします。モデルは、必要に応じてスキルの内容を検出し、読み込むことができます。スキルには、ワークフローが記述されている場合や、例が示されている場合、またはスクリプトが含まれている場合があります。ただし、スキルは自動的にスクリプトを実行したり、追加のマシン権限を与えたりすることはありません。

導入したスキルを有効にする前に、それらを確認してください。そのスキルの指示やファイルも、他のサードパーティ製のコードやプロンプトと同じように扱います。スキルの名前や説明は、モデルがそれを見つけやすいように、十分に具体的なものにしましょう。また、大きな参照情報は別途管理し、小さくて独立して使えるワークフローを優先しましょう。コントローラ側のレジストリやツールの呼び出し方については、[Skills](../guides/skills.md)を参照してください。

自動的なスキルやメモリのコンテキストは、会話の際に一時的に保存されます。これにより、各ターンごとにシステムのプロンプトを再入力する必要がなくなります。スキルの範囲を変更した場合、新しい会話を使ってテストを行うことができます。意図的に設定されたスキルは、最初の自動的なスナップショットとは異なります。

## 代表団とサブエージェント

エージェントは、その機能が利用可能な場合には、限定された作業をサブエージェントに委任することができます。子エージェントは、設定されたエージェントを使用しながら、独自のコミュニケーション処理を行うことができます。親エージェントは、タスクを調整し、子エージェントの結果を確認し、保存されている子エージェントの処理を続行することができます。子エージェントの活動は、親エージェントのチャットから確認できますが、その表示内容は独立して編集可能なものではありません。

独立したレビューや、別々のファイル領域の管理、または異なる仮説の調査といった、分割可能なタスクについては、デリゲーションを利用しましょう。子供には、具体的な目標や範囲、期待される結果を明確に伝えます。同じファイルに同時に書き込むことは避けてください。ただし、作業が明確に調整されている場合は除きます。

デリゲーションは、親が許可する範囲内に留まらなければなりません。親が使用できないマシンやMCPサービスへのアクセスを許可することはできません。子プロセスのポリシーは、親のポリシーを弱めることはできません。子プロセスは、モデルトークンや時間を独立して消費することができるので、コストや進捗状況を評価する際には、その活動や結果を確認する必要があります。

## 道具、行動、そして人工物

Agent Builderでは、利用可能なツールライブラリや高度な設定が提供されています。必要な機能のみを選択してください。OpenAPIスキーマで定義されているHTTPアクションについては、そのエンドポイント、認証要件、許可される操作などを確認した上で、そのアクションを使用してください。アクションには独自の認証方式があります。マシンの権限は、第三者のAPI認証情報を承認したり、取り消したりすることはありません。リモートでの変更が完了する前に、そのアクションの応答内容を確認してください。

生成されたUIコンテンツについては、記載されている通りにアーティファクトのレンダリングを設定してください。 [会話やプロジェクト](conversations.md)生成されたコードは、Controllerの信頼できる拡張体ではありません。

## 実用的なエージェントテンプレート

- **読み取り専用の調査員：** ログやソースコードを確認し、証拠を比較する。原因を報告するが、何も変更は行わない。
- **実施エージェント**：リポジトリを編集し、対象となるテストを実行し、違いや未解決の問題について報告する。必要に応じて、機密な操作を行う際には承認が必要となる。
- **モニタリングエージェント**：指定されたマシンを監視し、その状態やエラー、測定された進捗状況を報告します。明示的に許可されていない限り、ジョブを再起動することはありません。
- **リサーチエージェント**：ネットワーク内の情報を検索する機能を有し、原文を引用したり、証拠と推測を区別したりします。また、必要に応じてのみ機械的な処理を利用します。

これらのテンプレートは、組み込まれたプリセットではなく、指示に過ぎません。各エージェントの実際の権限や機能を設定し、それぞれのエージェントが担うべき役割に合わせて調整する必要があります。
