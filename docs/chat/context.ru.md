# Память, контекст и использование токенов

## Три разных вида государства

| Государство | Цель |
|---|---|
| История разговоров | Оригинальные сообщения и информация о действиях инструментов, сохраненная контролером. |
| Окно контекста | Этот набор инструкций, схем использования инструментов, информации о прошлом, кратких описаний и других данных, отправляемых в рамках конкретного запроса на модель. |
| Постоянная память | Удобно использовать уже известные факты и предпочтения в различных разговорах в соответствующем областе памяти. |

Длинная записанная беседа может превышать разрешенную область хранения данных модели, при этом вся история переписки не теряется. Память не означает, что вся история обращений к модели передается каждому запросу модели.

## Управление памятью

![Боковая панель управления памятью с демонстрационной записью](../assets/chat/memory-management.png)

Память активируется по умолчанию, если только пользователь не отключил её в своих настройках, не изменил параметры чата или не ограничил возможности использования памяти. Чтобы управлять данными, хранящимися в памяти, можно воспользоваться страницей управления памятью. Рекомендуется просить агента сохранять в памяти полезную информацию, правила и предпочтения, а также проверять результаты работы с данными в интерфейсе памяти.

При редактировании записей в памяти используйте ключи, состоящие только из строчных букв и подчеркиваний (например, `repository_conventions`). Предельная длина ключа составляет 10 000 символов. Установка может самостоятельно настроить ограничения на размер записей в памяти. Если какое-то значение отклоняется, необходимо выяснить причину ошибки, а не распределять секреты между различными ключами.

Память может использовать как общий личный пул данных, так и специфический для конкретного агента ресурс. Это зависит от настроек агента. Не храните в памяти ключи API, пароли или другие конфиденциальные данные. Отключение памяти предотвращает использование её в соответствующем режиме. Это не означает удаление уже сохраненных данных или исключение их из истории разговора.

При воздействии модель использует функцию `set_memory` для создания или обновления записей; пустая значения удаляется. Функция `find_memory` выполняет поиск записей по ключу или по определенным условиям; пустой запрос показывает все сохраненные данные. Дополнительный параметр `include_conversations` позволяет искать текст из других разговоров. Механизм pagination использует параметры `page` (по умолчанию 1) и `limit` (по умолчанию 10, максимум 50). При поиске истории учитывается текст разговоров, а не самые данные об использовании инструментов. Поиск выполняется на основе релевантности данных; поэтому необходимо использовать точные названия или термины для уточнения запроса.

Автоматическое вставление информации в память/навыки остается неизменным на протяжении всего диалога, что позволяет сохранять использование уже вставленных предложений. Изменение сохраненных данных не влияет на уже вставленные данные. Информация, сохраненная в памяти, может быть восстановлена при необходимости; также можно начать новый диалог, если необходимо использовать новую информацию.

## Контекстная способность

Необходимо указать реальные ограничения контекста для каждой модели в ее канале. Контроллер оценивает входные данные, видимые для модели, и выделяет место для выходных данных. Текущий показатель использования бюджета составляет 85% для сжатия данных и 5% для резервирования места. Эти значения могут быть приблизительными в случае незнакомых токенизаторов, мультимодальных запросов или специфических схем поставщиков данных.

Контекстная композиция может включать в себя системные инструкции, параметры конфигурации агентов, определения инструментов, дополнительные данные, полученные в результате обработки сообщений, а также результаты работы инструментов. Провайдер может использовать другой алгоритм разбиения текста на элементы или использовать дополнительные методы считывания данных. Рассматривайте этот контекст как инструкции по работе с системой, а не как гарантию от провайдера.

## Автоматическая упаковка

Когда бюджет контекста требует его сокращения, контролер создает или обновляет сводные данные о прошлом контексте. При этом сохраняется информация о последних изменениях для последующих запросов к модели. В сводных данных пытаются сохраниться цели, ограничения, принятые решения, прогресс, релевантные идентификаторы, результаты работы инструментов и следующие действия. Оригинальная информация о прошлом контекста остается доступной для изучения; сводные данные представляют собой приблизительную версию прошлого контекста, а не его точное воспроизведение.

Процесс компактизации выполняется до следующего запроса, требующем использования уменьшенного объема контекста. Если процесс суммирования не удался, система повторно пытается его выполнить в соответствии с правилами обработки ошибок. Не следует продолжать процесс без учета уже имеющегося объема данных. Необходимо проверить состояние компактизации и детальные ошибки, если процесс не может продолжаться. Связи между последовательными запросами и результатами обработки должны оставаться связанными. Завершенные результаты обработки не должны перезаписываться для уменьшения объема контекста.

Один очень большой файл или результат обработки все равно может превысить установленный лимит. Необходимо использовать ограниченные объемы данных, диапазоны файлов или сжатые версии данных. Большие результаты обработки следует сохранять в отдельные файлы, а затем извлекать нужные части данных, а не вставлять их в контекст модели постоянно.

## Суммарное использование ресурсов и количество кэшированных данных также имеют значение.

Отображение информации о использовании ресурсов и окна контекста отвечают разным задачам. Информация о входных/выходных операциях накапливается во время выполнения запросов, включая повторяющиеся элементы контекста. Метрики кэширования отражают данные о кэшировании данных, предоставляемые поставщиком. Определение объема активного контекста модели не включает все прошлые запросы.

Например, запрос с 20 000 входными токенами и другой запрос с 25 000 входными токенами потребуют в общей сложности 45 000 входных токенов. Но второй запрос потребует примерно 25 000 входных токенов из текущего объема контекста. Кэшированные данные не являются бесплатными, если только поставщик не предусматривает иное. Более большой объем контекста модели меняет ее способность к обработке данных, но не изменяет уже использованный объем ресурсов.

Уменьшение объема использования ресурсов может привести к снижению текущего уровня загрузки системы, но в то же время это повышает потребление ресурсов модели. Изменение моделей приводит к изменению ограничений, действующих в данной ситуации; однако предыдущее использование ресурсов не удаляется. Если поставщик не указывает точные значения использования ресурсов или метаданных кэш-памяти, то оценки и показатели могут быть неточными. Для финансовой корректировки следует использовать данные о расчетах и ценовые параметры поставщика, а не информацию, представленную в LSM-дисплее.

## Снизить затраты и сохранить полезную информацию.

Следует сохранять стабильность действий, связанных с использованием инструментов Agent. Необходимо избегать необходимости выводить слишком большой объем информации. Используйте целенаправленный подход при получении результатов. При необходимости передачи информации создайте краткий отчет с точными путями, идентификаторами объектов, полученными результатами и оставшимися вопросами. Проверяйте важные факты с помощью оригинальных данных или результатов работы инструментов. Не полагайтесь исключительно на сгенерированный отчет.
