# 대화와 프로젝트

## 채팅을 시작하고 계속 진행합니다.

새로운 대화를 열고, 채널/모델 또는 Agent를 선택한 후 메시지를 입력합니다. 채팅은 Controller에서 실행되며, 업데이트 정보는 브라우저로 전송됩니다. 페이지를 다시 로드하거나 탭을 닫는 것은 실행을 취소하는 것과 같은 효과가 없습니다. 중단하려면 ‘stop’ 버튼을 사용하고, 다른 작업을 시작하기 전에 결과 상태를 확인해야 합니다.

저장된 채팅 내용은 해당 모델/에이전트와의 연관성을 유지합니다. 다른 모델을 사용하고 싶다면 의도적으로 전환해야 합니다. 대화는 논리적 세션이 아닙니다. 대화에서는 사용자의 메시지와 모델의 메시지가 저장되지만, 논리적 세션에서는 도구 측의 작업 목표, 진행 상황, 계획 등이 저장됩니다. 긴 작업을 넘겨줄 때는 관련된 ID를 그대로 유지해야 합니다.

## 작업을 정리하고 찾습니다.

프로젝트를 사용하면 관련된 대화들을 한데 모아서 공유된 기기의 권한 설정을 정할 수 있습니다. 하나의 프로젝트에는 여러 개의 채팅방이 포함될 수 있습니다. 별도의 대화들이 모두 같은 맥락을 공유한다고 가정하지 말고, 적절한 프로젝트에 채팅방을 추가하거나 이동시키세요. 활성화된 프로젝트는 Agent에게 대화의 구조에 대한 정보를 제공할 수 있습니다.

태그는 대화들을 분류하는 역할을 합니다. 메시지의 북마크 기능은 개별 메시지를 나타내며, 유용한 결과로 다시 돌아가는 데 도움이 됩니다. 이러한 기능들은 대화를 고정시키는 기능과는 별개입니다. 채팅 제목, 검색 기능, 아카이브 기능, 읽지 않은 메시지 표시 기능 등을 사용하여 관리하기 쉬운 사이드바를 유지할 수 있습니다.

아카이브 기능을 사용하면, 대화 내용은 일반 목록에서 제거되지 않고 그대로 보관됩니다. 필요할 때는 아카이브 인터페이스를 통해 해당 대화를 다시 복원할 수 있습니다. 대화 내용을 삭제하는 것은 파일을 완전히 삭제하는 것과 같으므로, 이 방법을 아카이브 기능의 대체 수단으로 사용하지 마세요. 현재 구현 방식은 SQLite을 사용하여 대화 상태를 저장합니다. 따라서 기존의 압축된 Hosted Chat 아카이브 형식을 그대로 사용할 수는 없습니다.

## 메시지 처리 및 작업 실행

사용 가능한 메시지 제어 기능은 해당 메시지와 그 메시지의 현재 실행 상태에 따라 달라집니다. 적절하다면 해당 턴을 수정하거나 다시 시도할 수도 있고, 더 이상 필요하지 않다면 선택된 사용자/assistant의 턴을 삭제할 수도 있습니다. 삭제는 저장된 대화 기록을 변경하며, 이후의 상황에도 영향을 줄 수 있습니다. 하지만 셸 명령어나 원격 작업, Git push 등과 같은 외부적인 영향은 되돌릴 수 없습니다.

실패한 실행을 다시 시도할 때는, 먼저 발생한 오류 내용을 확인하고, 이미 완료된 도구의 작업 결과도 살펴보세요. 연결이 끊기기 전에 데이터가 저장될 수 있다면, 외부 상태를 확인한 후 다시 시도해야 합니다. 만약 다른 메시지가 대기 중이거나, 이미 어떤 작업이 진행 중이라면, 동시에 여러 작업이 발생할 것이라고 가정하지 말고, 표시된 제어판과 상태 정보를 참고하세요. ‘대기 중인 메시지’ 패널을 사용하면, 현재 처리 중인 작업을 확인할 수 있습니다. ‘지도 제어’ 기능은 현재 실행 중인 도구들이 완료된 후에 안전한 범위 내에서 지침을 제공합니다. 어떤 작업이든, 이미 완료된 도구의 효과는 되돌릴 수 없습니다.

## 첨부 파일, 미리보기, 그리고 아티팩트들

첨부 파일을 업로드하려면 ‘첨부 파일 관리’ 기능을 사용해야 합니다. 업로드된 파일의 크기는 최대 32MiB로 제한됩니다. 또한, 배포/프록시 요청에 따라 실제로 허용되는 파일 크기는 더 작아질 수 있습니다. 업로드된 파일들은 Controller에 저장되며, 모델을 통해 참조될 수 있습니다. 이미지를 처리하기 위해서는 이미지 데이터를 받아들일 수 있는 모델과 제공자가 필요합니다. 업로드는 관련이 없는 로컬 또는 원격 파일에 대한 접근 권한을 부여하는 것이 아닙니다.

생성된 파일을 요청할 때는, 사용할 경로, 형식, 내용을 명시해야 합니다. 결과가 존재하는지 확인한 후에야 그 파일을 공유할 수 있습니다. 채팅에서 지원되는 첨부파일이나 파일들을 다운로드하거나 미리 볼 수 있습니다. Worker에서 생성된 파일은 Controller로 전송되거나, 적절한 파일 링크로 제공될 수도 있습니다. 자세한 내용은 [파일 링크](../guides/file-links.md)을 참조하세요.

아티팩트 렌더링 기능을 사용하면, React, HTML, SVG, Markdown, Mermaid와 같은 요소들이 코드로만 표시되는 것이 아니라, 사이드 패널 형태로도 표시될 수 있습니다. Agent 아티팩트 설정에서 ‘Normal’ 모드는 표준 지침을 따르고, ‘shadcn/ui’ 모드는 컴포넌트 라이브러리에 대한 지침을 제공합니다. ‘Custom’ 모드는 기본적인 아티팩트 설정 없이도 렌더링된 콘텐츠를 제공합니다. 생성된 코드나 렌더링된 콘텐츠는 신뢰할 수 없는 것으로 간주되므로, 미리보기 외부에서 사용하기 전에 반드시 검토해야 합니다. 파일 기반의 오피스 미리보기 및 다운로드는 생성된 UI 아티팩트와는 별개입니다.

승인받지 못한 모델 제공업체에 보내야 하는 자격증, 개인 키, 또는 다른 문서들을 업로드하지 마세요. 첨부 파일의 삭제와 채팅 내용의 삭제는, 컴퓨터上에서 원본 파일을 삭제하는 것과는 별개입니다.

## 선호도/편견

채팅 및 사용자 선호사항, 예를 들어 도구의 켜기/끄기 기능이나 키보드 단축키 등은 WebUI를 통해 관리되며, 이 정보는 서버에 저장됩니다. 키보드의 동작을 설정하려면 설정을 열어보세요. 메시지를 보내는 것과 줄바꿈을 입력하는 것을 구분해야 합니다. 채팅 관련 도구의 켜기/끄기 기능은 Agent의 권한과는 별도로 설정해야 합니다. 자세한 내용은 [도구와 권한](permissions.md) 및 [메모리와 컨텍스트](context.md)를 참조하세요.

### 자동 대화 이름 지정

설정 → 채팅 → 대화에서 자동으로 이름을 지정하지 않거나, 새 대화의 이름을 한 번 지정하거나, 응답이 완료될 때마다 이름을 변경하도록 선택합니다. 기본값은 대화 모델을 사용하여 새 대화의 이름을 한 번 지정하는 것입니다. 구성된 채널에서 별도의 모델을 선택할 수도 있습니다. 이름 지정은 기본 응답이 완료된 후에만 실행되며 실패하거나 취소된 응답에서는 실행되지 않습니다. 제목은 사용자의 언어로 작업을 간략하게 설명합니다. 이름 지정 요청은 대화 컨텍스트와 별개이며 채팅 메시지를 추가하지 않습니다.
