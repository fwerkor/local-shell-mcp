# 智慧體與 Skill

## 何時建立智慧體

直接選擇模型聊天適合一次性問題或任務。智慧體是可以重複選擇、用於定時會話或被其他智慧體委派的持久配置。不同智慧體可以使用不同渠道、模型、指令及許可權策略。它們共享 Controller，但不一定共享記憶範圍和工具。

## 配置智慧體

在 WebUI 的智慧體管理中建立智慧體，填寫易於識別的名稱並選擇模型。指令應明確任務、期望輸出、約束和驗證要求。配置所需能力，儲存後即可使用該智慧體新建會話。

![Agent Builder 的指令、工具、審批與 Skill 設定](../assets/chat/agent-builder.png)

例如，可以為程式碼審查智慧體設定以下指令：

```text
基於當前 main 分支審查變更。
先檢查倉庫和測試結果，再得出結論。
不要修改檔案、推送提交或部署。
報告具體問題、檔案路徑和證據。
```

指令用於引導行為，並非授權邊界。如果審查者不應修改任何內容，需要將機器許可權設定為只讀，並移除不必要的外部 MCP 能力。參見[工具與許可權](permissions.md)。

建議為程式碼審查、實現、運維等不同職責建立獨立智慧體，分別選擇合適的模型與最小實用許可權。如果智慧體無法執行，先核實它引用的渠道和模型，再調整其他設定。

## Skill

Skill 打包可複用的指令及相關檔案，通常以 `SKILL.md` 為入口。在 WebUI 中管理 Skill，啟用所需 Skill，並使其對智慧體或聊天可用。模型可按需發現和載入內容。Skill 可以描述工作流、提供示例或指令碼，但不會自動執行指令碼，也不會授予額外機器許可權。

啟用匯入的 Skill 前應先審查。像對待第三方程式碼或提示詞一樣處理其中的內容。使用明確的名稱與描述，便於模型發現；將較大的參考資料單獨存放，優先構建簡潔且可獨立使用的工作流。Controller 登錄檔和工具呼叫詳見[Skill 指南](../guides/skills.md)。

自動 Skill 和記憶上下文在會話中使用快照，避免每輪重寫系統提示詞。顯式修改 Skill 使用範圍可以生效；測試修改後的自動上下文時，建議新建會話。模型主動載入的 Skill 與初始自動快照不同。

## 委派與子智慧體

能力可用時，智慧體可以把範圍明確的任務委派給子智慧體。子智慧體可以使用已配置的 Agent，並保留獨立的執行執行緒。父智慧體協調工作、讀取子任務結果，並可以繼續已儲存的子執行緒。可在父會話中檢視子智慧體活動，但此處並不是可獨立編輯的聊天視窗。

適合委派的任務包括獨立審查、不同檔案區域或不同假設的調查。為子智慧體明確目標、範圍和期望結果。除非已經協調好，不要讓多個子智慧體並行修改同一檔案。

委派必須遵守父智慧體的授權邊界，不能借此訪問父智慧體無權使用的機器或 MCP 服務；子智慧體的審批策略不能弱於父智慧體。子任務獨立消耗模型 Token 和時間，評估成本與進度時應檢查其活動和結果。

## 工具、Action 與 Artifact

Agent Builder 提供可用工具庫及高階配置。只選擇所需能力。對於透過 OpenAPI Schema 描述的 HTTP Action，接入前審查端點、認證要求與允許操作。Action 可以具有獨立認證；機器許可權並不會授權或撤銷第三方 API 憑證。認定遠端修改完成前，檢查 Action 響應。

生成式 UI 內容的渲染配置參見[會話與專案](conversations.md)。生成程式碼不屬於可信 Controller 擴充套件。

## 實用智慧體模板

- **只讀調查：** 檢查日誌和原始碼、比對證據、報告原因，不修改。
- **實現：** 修改倉庫、執行針對性測試、報告差異和未解決失敗；敏感操作按需審批。
- **監控：** 檢查指定機器，報告狀態、錯誤和實際進度；未經授權不重啟任務。
- **研究：** 啟用網路搜尋，引用原始文件，區分證據與推斷，只在需要時使用機器工具。

這些是指令模板，不是內建預設。應根據實際用途配置智慧體許可權與能力。
