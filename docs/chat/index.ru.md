# WebUI Chat

LSM WebUI Chat – это автономное рабочее пространство для ИИ-агентов, размещаемое в самом контроллере. Можно использовать собственную точку доступа к модели или поддерживаемый аккаунт. Модель получает доступ к своим инструментам и оборудованию. Не требуется использование внешнего клиента MCP. Внешние клиенты все равно могут подключаться к тому же контроллеру.

## Как все элементы сочетаются друг с другом

- **Контроллер:** это сервис на языке Python, который отвечает за размещение веб-приложений, обработку запросов, выполнение команд, а также управление процессами и сохранение постоянного состояния системы.
- **Канал/Средство связи:** Это модель подключения к API или авторизации поддерживаемого аккаунта. У этой модели есть свои учетные данные, протокол обмена данными, список моделей и другие настройки.
- **Модель:** идентификатор модели в рамках одного канала. То же самое идентификатор на двух каналах не означает, что речь идет о одном и том же конечном пункте.
- **Агент:** Это перезаправляемая конфигурация, которая включает в себя модель, инструкции, инструменты, навыки и разрешения.
- **Беседа:** сохраненные сообщения, настройки, история выполнения задач, а также связь между моделью/Агентом и соответствующими данными.
- **Проект:** группа разговоров с общими параметрами.
- **Рабочий процесс:** это целевая машина, которая подключена к внешнему ресурсу. Это не поставщик моделей, а также не отдельный сервер для обмена сообщениями.
- **Логическая сессия:** Это постоянная задача, связанная с использованием инструментов; она отличается от процесса ведения беседы. Использование такого подхода позволяет отслеживать цели, прогресс и ход выполнения задач с помощью инструментов.

Модель API получает контекст, доступный для модели, а также результаты работы инструментов. Контроллер выполняет разрешенные операции; модель не подключается напрямую к рабочему процессу, а также не получает ключ API модели. Браузер отображает процесс взаимодействия между участниками диалога и управляет действиями контроллера.

## Основные принципы работы.

Начинайте с использования ограниченного набора функций; проверяйте результаты работы инструментов перед возможностью внесения изменений. Модель может быть неверной, даже если инструмент работает корректно. Криптография учетных данных, хранение информации, доступ к машинам и одобрение действий инструментов – это отдельные аспекты. Изменение одного из этих параметров не автоматически означает одобрение другого. В частности, публичный чат-ендпоинт должен быть защищен как точка управления удаленными процессами.

Что касается внешней пути подключения к клиенту MCP, см. раздел [Подключение клиентов](../clients/connectivity.md). Что касается параметров, используемых в основном инструменте, см. раздел [Справка по инструментам](../reference/tools.md).
