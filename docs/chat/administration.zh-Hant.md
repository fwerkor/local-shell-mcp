# 管理與故障排查

## 部署架構

WebUI 前端由 Python Controller 提供，與 REST 和 MCP 端點共享同源服務。預設狀態後端是 SQLite。釋出的二進位制與 wheel 內建編譯後的前端資源；原始碼構建需要 JavaScript 工具鏈，執行已安裝的 Controller 不需要。Node.js、MongoDB、Meilisearch 和獨立 LibreChat 後端不再是執行時依賴。

參見[快速入門](../getting-started/quickstart.md)及[配置參考](../reference/configuration.md)。原始碼構建參見[WebUI 構建說明](https://github.com/fwerkor/local-shell-mcp/blob/main/ui/workspace/README.md)。

## 保護部署

使用可信 HTTPS 反向代理或隧道、認證與強憑證。將 Controller 置於適當的容器或虛擬機器隔離邊界，限制入站訪問並保護出站憑證。不要將未認證的執行端點暴露到公網。

代理應支援流式響應，避免快取到生成結束才傳送；需要 WebSocket 的介面應允許升級。為較長模型/工具請求設定合適的讀取和空閒超時，允許預期附件大小。配置的公開 URL 應與瀏覽器源地址及 OAuth 回撥一致。不要透過全域性禁用證書驗證來修復 TLS 問題。

模型請求由 Controller 發出，模型可見訊息、附件及工具結果可能傳送給所選上游 API。處理機密內容前評估提供方資料處理條款。同時保護外部 MCP 憑證與 Worker 邀請令牌。

## 狀態、備份與升級

預設狀態目錄為工作區下的 `.local-shell-mcp`，可透過 `LOCAL_SHELL_MCP_STATE_DIR` 修改。共享資料庫為 `lsm.sqlite3`。聊天、專案、設定、智慧體、記憶、定時任務和執行狀態儲存於服務端；附件、工作區檔案及其他產物可能位於資料庫外。

備份完整狀態目錄、目錄外的配置狀態、部署環境/憑證及相關工作區檔案。將備份視為敏感資料。僅備份資料庫可能遺漏附件或配置。使用已停止寫入的 Controller 或一致性 SQLite 備份機制；只複製執行中 SQLite 主資料庫檔案可能遺漏 WAL 中已提交資料。應在隔離測試部署中驗證恢復。

升級前記錄當前版本、執行路徑、配置、狀態位置及活躍任務。停止或安全排空相關執行，完成一致性備份，升級同一套安裝，並驗證認證、聊天曆史、模型生成、流式響應、Worker 和定時任務。啟動時支援舊狀態遷移到 SQLite；驗證遷移前保留舊檔案。不要用空測試資料目錄替換生產目錄。

如果資料庫遷移改變持久化狀態，回滾不只是替換二進位制。必要時恢復相容狀態，不要讓兩個獨立配置的 Controller 同時使用同一份活動儲存。

## 聊天失敗診斷

| 現象 | 優先檢查 |
|---|---|
| 無法載入 UI | Controller 程序、前端資源、URL、代理和認證 |
| 模型缺失 | 渠道配置、自動發現、模型 ID、賬戶授權 |
| 提供方返回 401/403 | API Key/賬戶、提供方許可權、所選渠道和協議 |
| HTTP 429 | 上游速率或額度限制、併發請求、賬戶/套餐狀態 |
| HTTP 400/413/422 | 請求相容性、輸入與視窗大小、附件限制、模型引數 |
| HTTP 5xx 或超時 | 提供方健康狀況、網路、推理服務容量、代理超時 |
| 流式輸出停止 | 重連或重新整理，檢視推理狀態和詳細錯誤 |
| 工具不可用 | 功能開關、智慧體能力、機器 ACL、OAuth Scope、Controller 開關 |
| Worker 離線 | Worker 註冊、出站連線、心跳及 Controller 日誌 |
| 等待審批/回答 | 開啟會話並檢查所請求操作 |
| 定時任務不執行 | 啟用狀態、時區、智慧體/渠道、目標、授權、上次執行 |

不要假定所有 HTTP 錯誤來自同一服務：區分 LSM 登入失敗、上游模型 API 錯誤、外部 MCP 錯誤和 Worker 傳輸錯誤。檢視詳細錯誤和相應 Controller 日誌；分享前刪除 Key、Bearer Token 和回撥 URL。

## 提供方重試與恢復

模型響應開始前，臨時連線錯誤和部分 HTTP 錯誤（408、429、500、502、503、504）可以進行有界退避重試。當前普通重試延遲為 1、2、4、8、16、30、30、30 秒（初始請求後最多八次重試）。HTTP Retry-After 可以將延遲延長至 120 秒；部分流式錯誤加入隨機抖動。重試預算針對單次模型請求，並非整個會話的累計計數。上下文壓縮有獨立的恢復路徑。額度耗盡導致的限流可能持續到提供方補充額度。自動重試不能保證最終成功，也不會讓訂閱獲得無限額度。

流式響應中斷與首個響應事件之前的失敗不同。不要依賴自動重放已經部分執行的工具序列。重試前檢查儲存的歷史和外部狀態。任務仍在執行時應重連，避免重複啟動。如果已經失敗，按需使用聊天恢復/重試控制元件；原會話無法繼續時，也可在新會話中明確交接任務。

上下文壓縮失敗應與普通推理錯誤分別調查。檢查實際視窗長度、模型相容性、超大工具結果及剩餘額度。參見[記憶與上下文](context.md)。

## Bug 報告內容

提供 LSM 版本/commit、安裝方式、作業系統、模型協議、脫敏端點型別、模型 ID、時間、復現步驟、相關會話/執行狀態和脫敏後的詳細錯誤。遠端問題另外提供 Worker 版本、機器名和 heartbeat/poll 狀態。儘量提供最小復現，不要傳送 API Key、OAuth Token、私密提示詞或無關個人資訊。
