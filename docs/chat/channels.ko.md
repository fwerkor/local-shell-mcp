# 채널과 모델들

## 채널을 설정해 주세요.

채팅창에서 모델 선택기를 열고 “채널 관리”를 선택합니다. **새 채널 추가**를 선택한 후, 연결 유형을 선택하고 필요한 정보를 입력한 다음 저장합니다. 그런 다음, 새로운 채팅을 위해 해당 채널에서 모델을 선택합니다. 맞춤형 에이전트를 사용하는 경우에는 에이전트 설정에서 해당 채널과 모델을 선택하면 됩니다.

채널들은 개인적인 채팅 설정이 아니라, Controller에 의해 관리됩니다. 인증된 환경에서는 채널 관리에 `admin:config` 범위가 필요합니다. 관리자는 채팅 사용자들에게 API 키를 전달하지 않고도 공유 채널을 설정할 수 있습니다.

![실제 채널 구성 대화상자에 모델 채널을 추가하세요.](../assets/chat/channel-settings.png)

일반적인 API 채널에는 이름, 제공자 프로토콜, 기본 URL, 인증 정보, 그리고 모델 식별자와 같은 정보가 포함됩니다. 선택된 엔드포인트에 대해 발급된 API 키를 사용해야 합니다. 여기서는 LSM 계정의 비밀번호를 사용해서는 안 됩니다. LSM은 Controller를 통해 요청을 보냅니다. 따라서 노트북에서 작동하는 URL이 Controller에서는 제대로 작동하지 않을 수 있습니다.

| 프로토콜 | 예시용 API 기본 URL | 사용하세요. |
|---|---|---|
| OpenAI Chat Completions | `https://api.openai.com/v1` | OpenAI와 호환되는 채팅 게이트웨이 및 로컬 인퍼스팅 서버 |
| OpenAI Responses | `https://api.openai.com/v1` | Responses API를 노출시키는 게이트웨이입니다. |
| 인류 원주민 | `https://api.anthropic.com/v1` | 인간주의적 메시지와 호환되는 API들 |
| Google Gemini 네이티브 | `https://generativelanguage.googleapis.com/v1beta` | Gemini는 Content와 호환되는 API를 제공합니다. |

프로바이더가 요구하는 기본 URL을 사용해야 합니다. `/chat/completions`와 같은 전체 요청 URL를 그대로 붙여넣는 것은 피해야 합니다. OpenAI 호환성을 주장하는 게이트웨이는 Chat Completions는 지원할 수 있지만, Response나 도구의 사용, 다중 입력 처리, 추론 기능 등은 지원하지 않을 수도 있습니다. 따라서 실제로 어떤 프로토콜을 지원하는지 확인해야 합니다. 예시된 URL들은 프로토콜의 예시일 뿐이며, 무료로 접근할 수 있거나 항상 사용 가능하다는 보장은 없습니다.

## 지역별 및 특정 환경에 맞는 엔드포인트들

OpenAI와 호환되는 서버가 Controller 자체에서 수신을 받도록 하려면, 기본 URL은 `http://127.0.0.1:8080/v1`가 될 수 있습니다. Docker 환경에서 실행할 경우, loopback은 물리적인 호스트를 의미하는 것이 아니라 해당 컨테이너를 의미합니다. Controller의 네트워크 이름공간에서 접근 가능한 주소를 사용해야 합니다. 단순히 원격 Worker를 등록한다고 해서 그 추론 API가 사용될 수는 없습니다.

이 모델의 URL 검증 기능은 HTTPS만을 지원합니다. 단, `localhost`, `127.0.0.1`, `::1`과 같은 리모트 호스트에서는 HTTP도 허용됩니다. LAN 주소나 Docker 서비스 이름을 가진 HTTP 엔드포인트는 반드시 HTTPS 게이트웨스를 통해 노출되어야 합니다. 더 이상 사용되지 않는 Hosted Chat 프라이빗 엔드포인트의 경우는 적용되지 않습니다. 기본 URL에는 임베디드된 자격증명, 파편 또는 쿼리 스트링이 포함되어서는 안 됩니다.

원격 엔드포인트에서는 TLS를 사용해야 합니다. 신뢰할 수 있는 프라이빗 게이트웨이에만 접근을 허용해야 하며, 인식 서버에서 모델 식별자를 확인해야 합니다. API 키는 절대로 팝업 메시지, 스크린샷, 쿼리 문자열, 또는 공개된 설정 정보에 포함되어서는 안 됩니다. 기존 채널을 편집할 때는 API 키를 비워두어서 저장된 키를 유지하세요. 서비스가 지원하는 경우에만 무키 연결을 사용해야 합니다.

## 환경에 의해 설정된 기본값들

내장된 OpenAI 프로필은 실행 전에 `LOCAL_SHELL_MCP_MODEL_BASE_URL`(또는 `OPENAI_BASE_URL`), `LOCAL_SHELL_MCP_MODEL`, `LOCAL_SHELL_MCP_MODEL_API_KEY`(또는 `OPENAI_API_KEY`)을 설정할 수 있습니다. 내장된 Anthropic 및 Google 프로필은 각각 `ANTHROPIC_API_KEY`와 `GOOGLE_KEY`/`GOOGLE_API_KEY`를 읽어들일 수 있습니다. 저장된 내장 프로필들은 환경에서 생성된 대체 설정보다 우선합니다. 여러 독립적인 엔드포인트를 사용할 경우에는 이름이 지정된 채널을 사용해야 합니다. 환경에 의해 설정된 기본값들은 서비스의 비밀을 보호하는 방법이 아닙니다.

## ChatGPT 계정의 권한 부여

이 채널에서는 일반적인 API 키 대신, 지원되는 ChatGPT 계정 인증 방식을 사용합니다. 채널 관리 메뉴에서 인증을 시작한 후, 공식 인증 페이지에 로그인하세요. 로컬 배포의 경우, 콜백 과정이 자동으로 완료될 수 있습니다. 만약 브라우저가 리플링크리스너에 접속할 수 없다면, 브라우저의 주소 표시줄에서 전체 콜백 URL을 복사하여 인증 대화상자에 붙여넣으세요. 이 수동적인 인증 방식에서는 리플링크 주소에서 연결 실패가 발생할 가능성이 있습니다.

콜백 URL은 자격 증명으로 취급하고 채팅에 보내거나 공개하지 마세요. Controller는 서버에 인증 정보를 저장하고 가능한 경우 자격 증명을 갱신합니다. 계정이 만료되거나 접근 권한이 취소되면 다시 인증하세요. 사용 가능한 모델, 요금제 제한 및 허용된 사용 방식은 상위 계정 서비스에서 결정하며 LSM은 추가 구독 할당량을 제공하지 않습니다.

## 모델 발견 및 맥락의 제한

자동 발견 기능을 활성화하여 제공자로부터 모델 정보를 요청할 수 있습니다. Controller는 정기적으로(현재는 10분마다) 데이터를 업데이트합니다. 수동으로 데이터를 업데이트할 수도 있습니다. 발견에 실패한 경우에도 이전에 저장된 모델 데이터는 그대로 유지됩니다. 만약 제공자가 호환되는 모델 목록 엔드포인트를 가지고 있지 않다면, 발견 기능을 비활성화하고 각 줄에 하나씩 모델 식별자를 입력해 주세요.

모델 검색은 OpenCode Go/Zen의 중첩된 `limit.context`, OpenRouter의 `context_length`, vLLM의 `max_model_len`, Gemini의 `inputTokenLimit` 등 명시적인 컨텍스트 창 메타데이터를 인식합니다. 최대 입력 길이만 보고되면 대체 값으로 사용하며 출력 제한과 모델 이름은 컨텍스트 용량을 결정하지 않습니다. 두 정보 모두 없으면 컨텍스트 창은 알 수 없는 상태로 유지됩니다.

각 모델에 대한 컨텍스트 창을 명확하게 지정해야 합니다. 개별 모델에 대한 값을 명시적으로 설정하면, 발견된 메타데이터를 무효화하거나 누락된 값을 보완할 수 있습니다. 편집기는 1에서 2,000,000개의 토큰까지 처리할 수 있습니다. 이는 구성 가능한 범위일 뿐, 해당 제공자가 그 정도의 성능을 지원한다는 보장은 아닙니다. 서버 측의 설정과 모델 자체의 제한 사항을 고려하여, 자신의 배포 환경에 가장 적합한 한계를 선택해야 합니다.

인식된 공식 공급자 엔드포인트의 경우 정확한 공급자 및 모델 ID로 공개 models.dev 카탈로그에서 누락된 컨텍스트 값을 채울 수 있습니다. 공급자 메타데이터가 이 대체 값보다 우선하며 수동 설정은 둘보다 우선합니다. 컨트롤러는 6시간 동안 공유 메모리 카탈로그 캐시를 사용하며 가져오기에 실패하면 마지막 정상 캐시를 유지하고 10분 후 다시 시도합니다. 채널 인증 정보, URL, 모델 ID는 models.dev에 전송하지 않습니다. 알 수 없는 엔드포인트와 일치하지 않는 ID는 공급자가 제한을 보고하지 않으면 계속 알 수 없는 상태로 남습니다.

## 샘플링, 추론, 그리고 사용 방법

채널/모델의 기본 설정은 선택된 제공자가 지원하는 요청 매개변수를 결정합니다. 채팅 구성기는 가능한 경우 그 이유를 제공할 수 있습니다. 각 프로토콜은 샘플링 및 추론 방식을 다르게 처리합니다. 특정 모델에서는 특정 옵션이 지원되지 않을 수도 있습니다. 먼저 제공자의 기본 설정을 확인한 후, 한 번에 하나의 설정을 변경해 나가세요.

LSM은 정확한 스트리밍 토큰 사용량을 요청할 수 있으며, 제공자가 해당 사용 옵션을 거부할 경우 대체 방법을 사용할 수도 있습니다. 사용량을 반환하지 않는 엔드포인트는 정확한 청구 내역이나 캐시 통계를 제공할 수 없습니다. 누적된 사용량과 현재의 용량 간의 차이에 대해서는 [메모리 및 컨텍스트](context.md)를 참조하십시오.

## 채널을 변경하거나 삭제하는 방법

대화는 선택된 모델/에이전트와 그 관련된 기록을 유지합니다. 엔드포인트를 변경하거나 프로바이더의 문제를 디버깅할 때는 반드시 모델을 변경해야 합니다. 사용 중인 채널을 이름을 바꾸는 경우는 참조를 보호하기 위해 제한됩니다. 사용 중인 채널을 삭제하는 경우에는 추가적인 확인이 필요합니다. 기록은 그대로 유지되지만, 삭제된 채널을 참조하는 에이전트와 채팅들은 계속 작동할 수 있도록 대체된 채널을 선택해야 합니다.

채널 설정은 서버 측에서 처리되며, 브라우저에서만 설정되는 것이 아닙니다. 인증 정보는 일반적인 채널 카탈로그 반환 메시지로 전달되지 않습니다. Controller 상태 디렉터리와 백업 파일들은 인증 정보가 포함된 데이터로 취급되어야 합니다.

## 연결 확인 목록

1. Controller가 API 호스트에 접속할 수 있으며, TLS 프로토콜이 정상적으로 작동하는지 확인해야 합니다.
2. 기본 경로, 프로토콜, 자격증 정보, 그리고 정확한 모델 ID를 확인해 주세요.
3. 새로운 발견을 할 수도 있고, 아니면 알려진 모델 중 하나를 수동으로 선택할 수도 있습니다.
4. 간단한 텍스트 메시지를 보내고, 그 다음에는 작은 도구를 사용해보세요.
5. 업스트림 HTTP 상태, 타임아웃, 또는 지원되지 않는 옵션과 관련된 오류 세부 정보를 확인하세요. 유효하지 않은 자격 증명을 반복적으로 시도하지 마세요.

속도 제한, 스트리밍 중단, 인증 오류 등을 처리하는 방법에 대해서는 [관리 및 문제 해결](administration.md)을 참조하십시오.
