# 智能体与 Skill

## 何时创建智能体

直接选择模型聊天适合一次性问题或任务。智能体是可以重复选择、用于定时会话或被其他智能体委派的持久配置。不同智能体可以使用不同渠道、模型、指令及权限策略。它们共享 Controller，但不一定共享记忆范围和工具。

## 配置智能体

在 WebUI 的智能体管理中创建智能体，填写易于识别的名称并选择模型。指令应明确任务、期望输出、约束和验证要求。配置所需能力，保存后即可使用该智能体新建会话。

![Agent Builder 的指令、工具、审批与 Skill 设置](../assets/chat/agent-builder.png)

例如，可以为代码审查智能体设置以下指令：

```text
基于当前 main 分支审查变更。
先检查仓库和测试结果，再得出结论。
不要修改文件、推送提交或部署。
报告具体问题、文件路径和证据。
```

指令用于引导行为，并非授权边界。如果审查者不应修改任何内容，需要将机器权限设置为只读，并移除不必要的外部 MCP 能力。参见[工具与权限](permissions.md)。

建议为代码审查、实现、运维等不同职责创建独立智能体，分别选择合适的模型与最小实用权限。如果智能体无法运行，先核实它引用的渠道和模型，再调整其他设置。

## Skill

Skill 打包可复用的指令及相关文件，通常以 `SKILL.md` 为入口。在 WebUI 中管理 Skill，启用所需 Skill，并使其对智能体或聊天可用。模型可按需发现和加载内容。Skill 可以描述工作流、提供示例或脚本，但不会自动执行脚本，也不会授予额外机器权限。

启用导入的 Skill 前应先审查。像对待第三方代码或提示词一样处理其中的内容。使用明确的名称与描述，便于模型发现；将较大的参考资料单独存放，优先构建简洁且可独立使用的工作流。Controller 注册表和工具调用详见[Skill 指南](../guides/skills.md)。

自动 Skill 和记忆上下文在会话中使用快照，避免每轮重写系统提示词。显式修改 Skill 使用范围可以生效；测试修改后的自动上下文时，建议新建会话。模型主动加载的 Skill 与初始自动快照不同。

## 委派与子智能体

能力可用时，智能体可以把范围明确的任务委派给子智能体。子智能体可以使用已配置的 Agent，并保留独立的执行线程。父智能体协调工作、读取子任务结果，并可以继续已保存的子线程。可在父会话中查看子智能体活动，但此处并不是可独立编辑的聊天窗口。

适合委派的任务包括独立审查、不同文件区域或不同假设的调查。为子智能体明确目标、范围和期望结果。除非已经协调好，不要让多个子智能体并行修改同一文件。

委派必须遵守父智能体的授权边界，不能借此访问父智能体无权使用的机器或 MCP 服务；子智能体的审批策略不能弱于父智能体。子任务独立消耗模型 Token 和时间，评估成本与进度时应检查其活动和结果。

## 工具、Action 与 Artifact

Agent Builder 提供可用工具库及高级配置。只选择所需能力。对于通过 OpenAPI Schema 描述的 HTTP Action，接入前审查端点、认证要求与允许操作。Action 可以具有独立认证；机器权限并不会授权或撤销第三方 API 凭证。认定远端修改完成前，检查 Action 响应。

生成式 UI 内容的渲染配置参见[会话与项目](conversations.md)。生成代码不属于可信 Controller 扩展。

## 实用智能体模板

- **只读调查：** 检查日志和源码、比对证据、报告原因，不修改。
- **实现：** 修改仓库、运行针对性测试、报告差异和未解决失败；敏感操作按需审批。
- **监控：** 检查指定机器，报告状态、错误和实际进度；未经授权不重启任务。
- **研究：** 启用网络搜索，引用原始文档，区分证据与推断，只在需要时使用机器工具。

这些是指令模板，不是内置预设。应根据实际用途配置智能体权限与能力。
