# 道具、機械、そして許可証

## 認可の段階

リストされているツールが実行可能であるということは、必ずしもそのツールを使用する権限があることを意味するわけではありません。実際のアクセス許可は、コントローラーの制限や認証されたプリンシパルのスコープ、マシンのポリシー、エージェントの機能、そしてツールの承認などが組み合わさって決まります。単に指示を出すだけでは、アクセスを実現することはできません。

登録されているマシンには、ローカルコントローラータスクも含まれます。この場合、チャットマシンのポリシーはデフォルトで読み取り/書き込みが可能となります。ただし、セキュリティ上の理由から、このデフォルト設定を制限することができます。不明なマシンの名前については、暗黙的な権限は与えられません。コントローラーは、ローカル実行やリモートワーカーの動作を個別に無効化することができます。

## マシンのアクセス

| アクセス | 意味 |
|---|---|
| なし | マシンの操作は利用できません。 |
| 読み取り専用 | 読み取り専用として分類されている操作のみが許可されます。任意のシェルやPythonの実行は、読み取り専用の操作には含まれません。 |
| 読み取り/書き込み | 認証されたユーザーは、他の制限に従って、読み取りや変更、実行などの操作を行うことができます。 |
| 継承 | 明示的なオーバーライドではなく、適用される上位レベルのデフォルト値を使用します。 |

![会話中のマシンの権限と承認モード](../assets/chat/machine-permissions.png)

マシン権限の設定で、グローバル既定値、プロジェクトの上書き設定、チャットごとの上書き設定を指定します。チャットの上書き設定はプロジェクトの設定に優先し、プロジェクトの設定はグローバル既定値に優先します。Agent はマシンごと、または既定のポリシーでアクセスをさらに制限できます。Agent の明示的な権限は、認証済み主体や Controller の制限を回避できません。

例：グローバルが読み書き可能、プロジェクトの上書き設定が読み取り専用、Agent が読み書き可能の場合、そのプロジェクトのチャットは、チャットのポリシーが明示的に上書きしない限り読み取り専用になります。ただしチャットで読み書き可能にしても、Agent の読み取り専用の上限を超えることはできません。

名前付きエージェントを使用したスケジュールされた実行では、そのエージェントのマシンポリシーや保存されている実行範囲が使用されます。通常のチャットマシンのオーバーライドは継承されません。[目標と自動化](automation.md)を参照してください。アンタッチドタスクには、専用の制限付きエージェントを使用してください。

## ツールの承認

| モード | 行動 |
|---|---|
| 自動 | 認可されたツールの呼び出しは、特別な承認が必要でない限り、何の手続きも必要ありません。ただし、別途の規定がある場合はその限りではありません。 |
| リスクのある業務を見直す | Controllerは、任意のシェルコマンドや、多くの外部呼び出しなど、危険とされる操作について、レビューを求めています。 |
| すべてのツールを確認する | 通常のツール呼び出しについて、承認を得る必要があります。 |

チャットの承認設定は Agent とグローバルの既定値を継承できます。既存の明示的な拒否ルールや承認ルールも有効です。子 Agent は親の承認モードを緩和できません。承認と権限は独立しています。拒否されたマシン操作を承認しても、そのマシンへのアクセス権限は付与されません。

承認する前には、実際の引数や宛先、および潜在的な副作用を確認してください。無人で運用されるワークフローの場合は、Agentや承認ポリシーを慎重に設定する必要があります。人の手による承認は、プロセスの進行を遅らせる可能性があります。単にプロンプトをなくすためにアクセス権を拡大してはいけません。

## ネイティブなツールと外部のMCPツール

ネイティブのツールは、LSMを通じてControllerや登録されたWorkers上で動作します。ツールレジストリには、ファイル操作、シェルやジョブの処理、ブラウザやGUIによる操作、リモート検出、ロジカルセッションなどの機能が含まれています。具体的な引数の構造については、[ツールのリファレンス](../reference/tools.md)を参照してください。マシンを接続する方法については、[リモートワーカー](../guides/remote-workers.md)をご覧ください。

WebUIで、ネストされたMCPサーバーを管理できます。サポートされている設定には、ローカルな標準I/OやリモートのHTTP通信が含まれます。また、サーバー固有の環境変数やヘッダーも利用可能です。チャットや関連するエージェントにおいて、外部MCP機能を有効にできます。エージェントは、利用可能な外部ツールを検出したり、それらを呼び出したりすることができます。ただし、そのツールの認証や承認は依然として適用されます。

外部 MCP ツールはネイティブのマシン ACL と独立して動作する場合があります。ローカルマシンへのアクセスが無効でも、外部のリモート API はリソースを変更できる場合があります。外部サービスの権限と認証情報は別途確認してください。機密ファイルを保持する Controller に信頼できない stdio サーバーをインストールしないでください。

## ユーザーに尋ねてみるか、機能のオン/オフを切り替えてみるか。

「Ask User」という機能を使えば、エージェントは推測するのではなく、構造化された人間の入力を要求できます。回答は、提示された質問に基づいて行われます。これは、拒否されたツールを無視するための許可を求めるものではありません。タスクが放置されている場合は、エージェントに対して、どのように不確実性を処理すべきかを指示します。また、完了したとは思わないまま、進行中のインタラクションを確認することもできます。

このコンポーザーでは、ネットワーク検索や外部のMCP、メモリなどの機能制御が可能です。これらの機能によって、モデルに利用可能な機能が決定されます。これらは認証とは別のものであり、機能を無効にしても過去の結果データは削除されません。ネットワーク検索はデフォルトで有効になっており、[Network search](../guides/webui-network-search.md)で説明されているように、読み取り専用のウェブツールを使用しています。

## 監査および検証

チャット内でのツールの呼び出しやその結果を確認してください。障害が発生した場合は、折りたたまれている詳細情報を展開して、問題を診断しましょう。Controllerのアドバイザリログには、ネイティブなツールの活動が記録されています。また、ジョブやセッションの状態も確認できます。APIの応答が成功したということは、ツールが結果を返したということですが、必ずしも要求された外部操作が目的を達成したわけではありません。書き込み内容やリモートジョブの状態、デプロイメントの状態などを独立して確認してください。 [アクティビティログ](../guides/audit-log.md).
