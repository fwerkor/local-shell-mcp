# 記憶、上下文與 Token 用量

## 三類狀態

| 狀態 | 用途 |
|---|---|
| 會話歷史 | Controller 儲存的原始訊息與工具活動 |
| 上下文視窗 | 某次模型請求所傳送的指令、工具定義、歷史、摘要及其他資料 |
| 持久記憶 | 在相應記憶範圍內跨會話複用的資訊與偏好 |

已儲存的長會話可以超過模型上下文視窗，而不丟失全部歷史。記憶也不意味著每次請求都會傳送帳戶的全部歷史。

## 管理記憶

![含範例項目的記憶管理側欄](../assets/chat/memory-management.png)

記憶預設啟用，除非使用者設定、會話開關、部署或智慧體能力限制將其關閉。透過記憶管理頁面檢查和編輯條目。可以要求智慧體記住有用事實、專案約定或偏好，並在記憶介面驗證結果。

編輯記憶條目時，鍵名僅使用小寫英文字母和下劃線（例如 `repository_conventions`）。預設值長度限制為 10,000 字元；部署可以設定其記憶儲存限制。如果條目被拒絕，應檢視錯誤，而非將秘密拆分到多個鍵。

根據智慧體設定，可以共享個人記憶池，也可以使用智慧體獨立記憶。不要儲存 API Key、密碼或不必要的敏感資訊。關閉記憶會阻止在對應範圍內使用它，並不等於刪除現有條目或清除會話歷史中的相關內容。

工具可用時，模型透過 `set_memory` 新建或更新條目；空值刪除條目。`find_memory` 按查詢詞或精確鍵名檢索，空查詢列出已有記憶。可選的 `include_conversations` 引數同時檢索其他會話文字。分頁引數為 `page`（預設 1）和 `limit`（預設 10，最大 50）。歷史檢索針對會話文字而非原始工具呼叫記錄。結果按相關性排序，建議使用精確的名稱和術語，並按需調整查詢。

自動記憶/Skill 注入在會話各輪間保持穩定，以複用提供方提示詞字首快取。修改已儲存記憶不會回溯重寫此前注入的快照。顯式記憶檢索可訪問當前資料；需要重新注入新上下文時新建會話。

## 上下文容量

在渠道中填寫各模型的實際上下文限制。Controller 估計模型可見輸入併為輸出預留空間；當前預算實現預設壓縮比例 85%、預留比例 5%，具體取決於實際模型與執行設定。對於未知 tokenizer、多模態請求或提供方專有格式，計數可能只是近似值。

上下文構成可能包括系統指令、智慧體設定、工具定義、附件、歷史訊息和工具結果。提供方可能使用不同 tokenizer 或計入額外內部 Token。介面數值用於執行判斷，不保證提供方一定接受請求。

## 自動上下文壓縮

當上下文預算要求壓縮時，Controller 建立或更新較早上下文的檢查點摘要，並保留近期歷史用於後續模型請求。摘要嘗試保留目標、約束、決策、進展、相關標識、工具結果及後續步驟。原始儲存歷史仍可檢視；摘要是模型生成的近似內容，不是完美復現。

壓縮在下一次需要縮小上下文的請求前完成。如果摘要失敗，引擎按照錯誤處理機制重試，不應直接使用已超預算的輸入繼續推理。如果無法繼續，應檢視壓縮狀態和詳細錯誤。近期訊息及工具呼叫與結果之間的對應關係必須保持完整。已完成的舊工具結果不會僅為縮小上下文而被漸進式改寫。

單個超大附件或工具結果仍可能超過預算。要求限制輸出、指定檔案範圍或生成摘要；大型結果可以儲存至檔案，再按需讀取，而不是反覆放入模型上下文。

## 累計用量與快取命中

會話用量與上下文視窗回答不同問題。輸入/輸出用量按會話中每次模型請求累加，包括重複傳送的上下文。快取指標反映提供方報告的提示詞快取情況（如有）。上下文佔用衡量當前模型視窗，不累加過去所有請求。

例如，第一次請求包含 20,000 個輸入 Token，第二次包含 25,000 個，累計輸入消耗為 45,000 Token，但第二次請求當前輸入上下文約為 25,000 Token。快取 Token 是否免費取決於提供方價格。增大模型視窗只會改變容量，不會改變歷史消耗。

壓縮可以降低當前佔用，但也會產生額外模型消耗。切換模型改變適用視窗長度，不會清除之前的消耗。提供方不返回精確用量或快取資料時，估算值與指標可能不完整。財務對賬應參考提供方賬單及價格，而非僅依據 LSM 顯示。

## 降低成本並保留有效上下文

保持智慧體指令穩定，避免不必要的大型工具輸出，使用精準檢索。無關任務應新建會話。交接任務時儲存包含精確路徑、commit ID、觀測結果和未解決問題的簡潔檢查點。重要事實應與原始資料或工具結果核對，不能只依賴生成的摘要。
