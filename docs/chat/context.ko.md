# 메모리, 컨텍스트, 그리고 토큰 사용량

## 세 가지 다른 종류의 국가

| 주정부 | 목적 |
|---|---|
| 대화 기록/통화 내역 | Controller에 의해 저장된 원본 메시지와 도구 활동들입니다. |
| 콘텐츠 창 | 특정 모델 요청에서 전송되는 명령어들의 하위 집합, 도구 스키마, 이력, 요약 내용 등의 데이터들입니다. |
| 지속적인 기억 | 반복적으로 사용할 수 있는 사실과 선호도들은, 관련된 메모리 범위 내에서의 대화들을 통해 쉽게 접근할 수 있습니다. |

오랫동안 저장된 대화 내용은 모델의 컨텍스트 창을 초과할 수 있지만, 그동안의 모든 기록이 손실되는 것은 아닙니다. 메모리는 전체 계정 내역이 모든 모델 요청에 전송된다는 의미는 아닙니다.

## 메모리 관리

![예제 항목이 있는 메모리 관리 사이드바](../assets/chat/memory-management.png)

메모리는 기본적으로 활성화되어 있습니다. 다만, 사용자의 설정이나 채팅 기능의 활성/비활성 상태, 또는 배포/에이전트 기능의 제한으로 인해 메모리가 비활성화될 수도 있습니다. 메모리 관리 페이지를 사용하여 저장된 데이터를 확인하고 수정할 수 있습니다. 에이전트에게 유용한 정보나 프로젝트 관련 규칙, 선호 사항 등을 기억하도록 요청할 수 있으며, 메모리 인터페이스에서 결과를 확인할 수도 있습니다.

메모리 항목을 편집할 때는 소문자와 아래첨자를 포함하는 키를 사용해야 합니다(예: `repository_conventions`). 기본적으로 메모리 저장소의 길이는 10,000자로 제한됩니다. 하지만 설치 과정에서 메모리 저장소의 제한을 조정할 수 있습니다. 항목이 거부된 경우, secrets를 여러 키로 분할하는 대신 오류 내용을 확인해야 합니다.

메모리는, Agent의 설정에 따라, 공유된 개인용 데이터 저장소를 사용할 수도 있고, Agent에 특화된 범위 내에서 데이터를 저장할 수도 있습니다. API 키나 비밀번호, 또는 불필요한 민감한 데이터는 메모리에 저장해서는 안 됩니다. 메모리를 비활성화하면 해당 범위 내에서 메모리가 사용되지 않게 됩니다. 이는 기존에 저장된 데이터를 삭제하거나, 대화 기록에서 관련 내용을 제거하는 것과는 다릅니다.

노출된 상태에서, 이 모델은 다음과 같은 작업을 수행합니다. `set_memory` 항목을 생성하거나 업데이트할 때, 비어 있는 값은 해당 항목을 삭제합니다. `find_memory` 쿼리나 정확한 키를 사용하여 항목을 검색할 수 있으며, 빈 쿼리는 저장된 메모리를 나열합니다. 선택적 기능입니다. `include_conversations` 플래그 검색 기능은 다른 대화 내용도 함께 검색할 수 있습니다. 페이지 번호는 다음과 같습니다: `page` (기본값: 1) 그리고 `limit` 기본값은 10이며, 최대값은 50입니다. 이 역사 검색 기능은 원시적인 도구 호출 기록이 아니라, 대화 내용을 기반으로 검색합니다. 검색 결과는 관련성에 따라 순위가 매겨지므로, 정확한 이름이나 용어를 사용하고 필요하다면 질의를 더 세밀하게 조정해야 합니다.

자동 메모리/스킬 삽입 기능은 대화가 진행되는 동안 일정하게 유지됩니다. 이를 통해 재사용 가능한 제공자 프롬프트의 전체 구조가 보존됩니다. 저장된 메모리를 편집해도 이미 삽입된 데이터는 다시 수정되지 않습니다. 명시적인 메모리 검색 기능을 사용하면 현재 저장된 데이터를 확인할 수 있습니다. 새로운 대화가 필요한 경우, 새로 삽입된 콘텐츠를 활용하여 새로운 대화를 시작할 수 있습니다.

## 컨텍스트 용량

각 모델의 실제 컨텍스트 제한을 해당 채널에 설정합니다. Controller는 모델이 볼 수 있는 입력을 추정하고, 출력에 필요한 공간도 확보합니다. 현재 예산 구현 방식은 85%의 압축 비율과 5%의 예비 비율을 기본으로 합니다. 이 값은 실제 모델 및 실행 시간 설정에 따라 변경될 수 있습니다. 이러한 계산 결과는 익숙하지 않은 토크셰이너나 다중 모달 요청, 또는 제공자별 스키마의 경우에는 대략적인 값일 수 있습니다.

컨텍스트 구성에는 시스템 명령어, 에이전트 설정, 도구 정의, 첨부 파일, 이전 메시지 및 도구의 결과 등이 포함됩니다. 제공자는 다른 토크나이저를 사용하거나 추가적인 내부 토큰을 계산할 수도 있습니다. 여기서 표시된 내용은 운영 지침으로 간주해야 하며, 제공자의 보증으로 해석해서는 안 됩니다.

## 자동 압축

컨텍스트 예산이 축소되어야 할 경우, Controller는 이전의 컨텍스트 정보를 요약하여 저장합니다. 그리고 최근의 정보는 이후의 모델 요청에 사용됩니다. 이 요약된 정보에는 목표, 제약 조건, 결정 사항, 진행 상황, 관련 식별자, 도구의 결과 및 다음에 취해야 할 조치들이 포함됩니다. 원본 저장된 정보는 여전히 확인할 수 있습니다. 하지만 요약된 정보는 모델이 생성한近似된 결과일 뿐, 완벽한 복제물은 아닙니다.

다음 요청이 발생하기 전에 압축 작업이 이루어집니다. 이때, 줄어든 컨텍스트가 필요합니다. 만약 요약 작업이 실패한다면, 엔진은 오류 처리 방식에 따라 다시 시도해야 합니다. 이미 과도하게 커진 입력 데이터를 그대로 사용하는 것은 피해야 합니다. 압축 작업이 계속 진행되지 않는 경우, 압축 상태와 세부적인 오류 정보를 확인해야 합니다. 최근의 메시지들과 도구 호출/결과 간의 관계는 일관되어야 합니다. 완료된 이전의 도구 결과들은 단순히 컨텍스트를 줄이기 위해 계속해서 다시 작성되는 것은 아닙니다.

단일한 결과물을 얻는 것만으로도 예산을 초과할 수 있습니다. 제한된 출력 크기나 파일 범위를 요청하는 것이 좋습니다. 대용량의 결과물들을 파일로 저장하여, 반복적으로 모델에 삽입하는 대신 특정 부분만을 가져와서 사용할 수 있도록 하세요.

## 누적된 사용량 및 캐시 성능

세션 사용량 표시와 컨텍스트 창은 서로 다른 질문에 대한 답변을 제공합니다. 입력/출력 수치는 대화 중에 발생하는 모든 요청에 걸쳐 누적됩니다. 캐시 메트릭스는 제공자가 보고하는 프롬프트 캐싱 정보를 나타냅니다. 컨텍스트 점유율은 활성 상태인 모델의 시간을 측정하며, 과거의 모든 요청을 합산하지 않습니다.

예를 들어, 20,000개의 입력 토큰을 포함하는 요청과, 또 다른 25,000개의 입력 토큰을 포함하는 요청이 함께 발생한다면, 총 45,000개의 입력 토큰이 소모됩니다. 하지만 두 번째 요청에서는 현재의 컨텍스트 용량 내에서 약 25,000개의 입력 토큰만 사용됩니다. 캐싱된 토큰들은 제공자의 정책에 따라야만 무료로 사용할 수 있습니다. 더 큰 모델 컨텍스트 제한은 용량을 변화시키지만, 이전에 소모된 사용량에는 영향을 미치지 않습니다.

압축 처리하면 현재의 사용량을 줄일 수 있지만, 동시에 모델의 소모량도 증가합니다. 모델을 전환하면 적용되는 제한사항이 변경되지만, 이전의 사용량은 삭제되지 않습니다. 만약 제공자가 정확한 사용량이나 캐시 메타데이터를 누락한다면, 추정치와 지표가 불완전해질 수 있습니다. 재무 조정을 할 때는 제공자의 청구 데이터와 가격 정보를 사용해야 하며, 단순히 LSM 화면의 정보만을 참고해서는 안 됩니다.

## 비용을 줄이고 유용한 정보를 보존합니다.

Agent의 명령어를 안정적으로 유지하고, 불필요한 대량의 출력 결과를 피하며, 집중된 검색 방식을 사용합니다. 관련 없는 작업은 별도의 대화로 처리해야 합니다. 전환이 필요할 경우, 정확한 경로, 커밋 ID, 관찰된 결과, 남은 질문들 등을 포함한 간결한 점검점을 저장해야 합니다. 중요한 사실들은 원본 소스나 도구의 결과와 비교하여 확인해야 하며, 단순히 생성된 요약 정보만을 의존해서는 안 됩니다.
