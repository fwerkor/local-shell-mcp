# 记忆、上下文与 Token 用量

## 三类状态

| 状态 | 用途 |
|---|---|
| 会话历史 | Controller 保存的原始消息与工具活动 |
| 上下文窗口 | 某次模型请求所发送的指令、工具定义、历史、摘要及其他数据 |
| 持久记忆 | 在相应记忆范围内跨会话复用的信息与偏好 |

已保存的长会话可以超过模型上下文窗口，而不丢失全部历史。记忆也不意味着每次请求都会发送账户的全部历史。

## 管理记忆

记忆默认启用，除非用户设置、会话开关、部署或智能体能力限制将其关闭。通过记忆管理页面检查和编辑条目。可以要求智能体记住有用事实、项目约定或偏好，并在记忆界面验证结果。

根据智能体配置，可以共享个人记忆池，也可以使用智能体独立记忆。不要保存 API Key、密码或不必要的敏感信息。关闭记忆会阻止在对应范围内使用它，并不等于删除现有条目或清除会话历史中的相关内容。

工具可用时，模型通过 `set_memory` 新建或更新条目；空值删除条目。`find_memory` 按查询词或精确键名检索，空查询列出已有记忆。可选的 `include_conversations` 参数同时检索其他会话文本。分页参数为 `page`（默认 1）和 `limit`（默认 10，最大 50）。历史检索针对会话文本而非原始工具调用记录。结果按相关性排序，建议使用精确的名称和术语，并按需调整查询。

自动记忆/Skill 注入在会话各轮间保持稳定，以复用提供方提示词前缀缓存。修改已保存记忆不会回溯重写此前注入的快照。显式记忆检索可访问当前数据；需要重新注入新上下文时新建会话。

## 上下文容量

在渠道中填写各模型的实际上下文限制。Controller 估计模型可见输入并为输出预留空间；当前预算实现默认压缩比例 85%、预留比例 5%，具体取决于实际模型与运行配置。对于未知 tokenizer、多模态请求或提供方专有格式，计数可能只是近似值。

上下文构成可能包括系统指令、智能体配置、工具定义、附件、历史消息和工具结果。提供方可能使用不同 tokenizer 或计入额外内部 Token。界面数值用于运行判断，不保证提供方一定接受请求。

## 自动上下文压缩

当上下文预算要求压缩时，Controller 创建或更新较早上下文的检查点摘要，并保留近期历史用于后续模型请求。摘要尝试保留目标、约束、决策、进展、相关标识、工具结果及后续步骤。原始保存历史仍可查看；摘要是模型生成的近似内容，不是完美复现。

压缩在下一次需要缩小上下文的请求前完成。如果摘要失败，引擎按照错误处理机制重试，不应直接使用已超预算的输入继续推理。如果无法继续，应查看压缩状态和详细错误。近期消息及工具调用与结果之间的对应关系必须保持完整。已完成的旧工具结果不会仅为缩小上下文而被渐进式改写。

单个超大附件或工具结果仍可能超过预算。要求限制输出、指定文件范围或生成摘要；大型结果可以保存至文件，再按需读取，而不是反复放入模型上下文。

## 累计用量与缓存命中

会话用量与上下文窗口回答不同问题。输入/输出用量按会话中每次模型请求累加，包括重复发送的上下文。缓存指标反映提供方报告的提示词缓存情况（如有）。上下文占用衡量当前模型窗口，不累加过去所有请求。

例如，第一次请求包含 20,000 个输入 Token，第二次包含 25,000 个，累计输入消耗为 45,000 Token，但第二次请求当前输入上下文约为 25,000 Token。缓存 Token 是否免费取决于提供方价格。增大模型窗口只会改变容量，不会改变历史消耗。

压缩可以降低当前占用，但也会产生额外模型消耗。切换模型改变适用窗口长度，不会清除之前的消耗。提供方不返回精确用量或缓存数据时，估算值与指标可能不完整。财务对账应参考提供方账单及价格，而非仅依据 LSM 显示。

## 降低成本并保留有效上下文

保持智能体指令稳定，避免不必要的大型工具输出，使用精准检索。无关任务应新建会话。交接任务时保存包含精确路径、commit ID、观测结果和未解决问题的简洁检查点。重要事实应与原始资料或工具结果核对，不能只依赖生成的摘要。
