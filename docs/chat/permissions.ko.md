# 도구, 머신, 권한

## 권한 부여 층

도구가 목록에 표시되어 있다고 해서 그 도구를 실행할 수 있는 권리가 있는 것은 아닙니다. 실제 권한은 Controller의 제한과 인증된 사용자의 권한, 머신 정책, Agent의 기능, 도구의 승인을 모두 포함합니다. 단순히 지시만으로는 접근 권한을 부여할 수 없습니다.

등록된 머신들은, 로컬 컨트롤러 타겟을 포함하여, 기본적으로 채팅 머신 정책에 따라 읽기/쓰기 권한을 가집니다. 하지만 민감한 환경에서는 이러한 기본 설정을 제한해야 합니다. 알 수 없는 머신 이름은 암시적 권한을 받지 않습니다. 컨트롤러는 로컬 실행이나 원격 워커 기능을 개별적으로 비활성화할 수 있습니다.

## 기계 접근 허가

| 접근/접속 | 의미/ 의미 |
|---|---|
| 없음 | 기계 작동이 불가능합니다. |
| 읽기 전용 | 읽기 전용으로 분류된 작업들만 허용됩니다. 임의의 셸이나 파이썬 코드를 실행하는 것은 읽기 전용 작업으로 간주되지 않습니다. |
| 읽기/쓰기 | 승인된 사용자만이 읽거나 수정/실행할 수 있습니다. 단, 다른 제한 사항들이 존재합니다. |
| 상속 | 해당하는 고수준의 기본 설정을 사용해야 하며, 명시적인 재정렬은 피해야 합니다. |

대화 중에 기계의 권한 및 승인 모드에 대한 설명입니다. ![대화 중에 기계의 권한 및 승인 모드](../assets/chat/machine-permissions.png)

머신 권한 설정에서 전역 기본값, 프로젝트별 재정의, 채팅별 재정의를 지정합니다. 채팅별 재정의가 프로젝트별 재정의보다 우선하며, 프로젝트별 재정의는 전역 기본값보다 우선합니다. Agent는 머신별 또는 기본 정책에 따라 접근을 추가로 제한할 수 있습니다. Agent에 명시된 권한으로 인증된 주체나 Controller의 제한을 우회할 수는 없습니다.

예를 들어 전역 정책은 읽기/쓰기, 프로젝트 재정의는 읽기 전용, Agent 권한은 읽기/쓰기인 경우, 해당 프로젝트의 채팅은 채팅 정책이 명시적으로 재정의하지 않는 한 읽기 전용입니다. 채팅에서 읽기/쓰기로 재정의하더라도 Agent의 읽기 전용 제한을 초과할 수 없습니다.

명명된 에이전트를 사용하는 예약된 실행에서는, 해당 에이전트의 머신 정책과 저장된 실행 범위를 사용합니다. 일반적인 채팅 머신의 설정을 상속받는 것은 아닙니다. 자세한 내용은 [목표와 자동화](automation.md)를 참조하십시오. 무인 작업을 수행하기 위해서는 별도의 제한된 에이전트를 사용해야 합니다.

## 도구 승인

| 모드 | 행동/습관 |
|---|---|
| 자동 | 승인된 도구의 호출은, 별도의 명시적인 정책이 요구하지 않는 한, 추가적인 승인 절차 없이 진행됩니다. |
| 위험한 작업 검토 | Controller는 위험한 작업들에 대해 검토를 요청합니다. 여기에는 임의의 셸 명령어나 많은 외부 호출들이 포함됩니다. |
| 모든 도구 검토 | 일반적인 도구의 사용에 대한 승인을 요청합니다. |

채팅의 승인 설정은 Agent 및 전역 기본값을 상속할 수 있습니다. 기존의 명시적인 거부 또는 승인 규칙은 계속 적용됩니다. 하위 Agent는 상위 Agent의 승인 모드를 완화할 수 없습니다. 승인은 권한과 별개입니다. 거부된 머신 작업을 승인해도 해당 머신에 대한 접근 권한은 부여되지 않습니다.

승인하기 전에 실제 인수 값, 대상, 그리고 잠재적인 부작용을 반드시 검토해야 합니다. 무인 워크플로우의 경우, Agent와 승인 정책을 신중하게 설정해야 합니다. 인간의 승인이 필요한 경우, 진행 속도가 느려질 수 있습니다. 단순히 프롬프트를 제거하기 위해 접근 권한을 넓히는 것은 좋지 않습니다.

## 네이티브 및 외부 MCP 도구들

네이티브 도구들은 Controller와 등록된 Workers를 LSM을 통해 처리합니다. 도구 레지스트에는 파일 작업, 셸 및 작업 처리, 브라우저 및 GUI 관련 작업, 원격 검색, 논리적 세션 관리 등 다양한 기능들이 포함됩니다. 정확한 인수 구조에 대해서는 [도구 참조](../reference/tools.md)을 참고하세요. 머신들을 연결하는 방법에 대해서는 [원격 작업자](../guides/remote-workers.md)을 참고하세요.

WebUI를 통해 중첩된 MCP 서버들을 관리할 수 있습니다. 지원되는 구성에는 로컬 stdio 및 원격 HTTP 전송 방식이 포함됩니다. 서버별 환경 변수나 헤더도 사용할 수 있습니다. 채팅 기능과 관련된 Agent에서 외부 MCP 기능을 활성화할 수 있습니다. Agent는 사용 가능한 외부 도구들을 발견하고 호출할 수 있으며, 그들의 권한 및 승인 절차는 여전히 적용됩니다.

외부 MCP 도구는 기본 머신 ACL과 독립적으로 작동할 수 있습니다. 로컬 머신 접근이 비활성화되어 있어도 외부 원격 API는 리소스를 변경할 수 있습니다. 외부 서비스의 권한과 자격 증명을 별도로 검토하세요. 민감한 파일을 보관하는 Controller에 신뢰할 수 없는 stdio 서버를 설치하지 마세요.

## 사용자에게 질문하거나 기능을 켜고 끄는 것도 가능합니다.

‘Ask User’ 기능을 사용하면, 에이전트는 추측하는 대신 구조화된 인간의 입력을 요청할 수 있습니다. 질문을 통해 응답을 받는 방식입니다. 이는 정보를 요청하는 것이며, 거부된 작업을 무시할 권한을 주는 것은 아닙니다. 작업이 방치된 상태일 경우, 에이전트에게 불확실한 상황을 어떻게 처리해야 하는지 지시해야 합니다. 또한, 진행 중인 상호작용들을 확인한 후에야 작업이 완료된 것으로 간주할 수 있습니다.

작곡자는 네트워크 검색, 외부 MCP 및 메모리와 같은 기능들을 제어할 수 있습니다. 이러한 기능들은 모델에 제공될 수 있는 기능들을 결정합니다. 이 기능들은 권한과는 별개로 작동하며, 특정 기능을 비활성화해도 과거의 결과는 삭제되지 않습니다. 네트워크 검색은 기본적으로 활성화되어 있으며, [Network search](../guides/webui-network-search.md)에 설명된 대로 읽기 전용 웹 도구를 사용합니다.

## 감사 및 검증

채팅 창에서 도구의 호출과 그 결과를 확인하세요. 오류가 발생할 경우, 축소된 세부 정보를 확장하여 확인할 수 있습니다. Controller의 감사 로그에는 네이티브 도구의 활동이 기록됩니다. 작업/세션 상태는 현재 진행 중인 작업을 나타냅니다. API 응답이 성공했다고 해서 반드시 요청된 외부 작업이 목적을 달성했다는 의미는 아닙니다. 작성된 데이터, 원격 작업의 상태, 배포 상태 등을 별도로 확인해야 합니다. 자세한 내용은 [감사 로그](../guides/audit-log.md)을 참조하세요.
