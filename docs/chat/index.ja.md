# WebUI Chat

LSM WebUI Chatは、Controllerに内蔵されている、自己ホスト型のAIエージェントワークスペースです。自分自身でモデルのエンドポイントを持ってくるか、またはサポートされているアカウントを使用してください。そうすれば、モデルは自分のツールやマシンにアクセスできます。外部のMCPクライアントを使う必要はありません。外部のクライアントも、同じControllerに接続することができます。

## どのようにして、これらの要素が一緒になっているのか

- **Controller：**ブラウザアプリケーションを実行し、リクエストを処理し、ツールを実行し、スケジュール処理を行い、持続的な状態を管理する、Pythonで構成されるサービスです。
- **チャネル**：モデルのAPI接続や、サポートされているアカウントの認証手段です。独自の認証情報、プロトコル、モデル一覧、設定などが用意されています。
- **モデル**：チャンネル内でのモデルの識別子です。2つのチャンネルで同じ識別子が使われていても、それは同じエンドポイントを意味するわけではありません。
- **エージェント**：モデル、指示、ツール、スキル、権限などを組み合わせて作られる、再利用可能な設定です。
- **会話内容：**保存されたメッセージ、設定情報、実行履歴、およびモデル/エージェントの関連情報。
- **プロジェクト**：共通の設定を共有する、一連の会話のことです。
- **ワーカー**：アウトバウンドで接続される実行対象です。モデルプロバイダーや、別のチャットサーバーではありません。
- **ロジカルセッション**：ツール側で実行されるタスクの識別子であり、会話IDとは異なります。チャットでは、目標や進捗状況、およびツールの作業内容を追跡するために、このロジカルセッションを使用できます。

このモデルAPIは、モデルが利用できるコンテキストやツールの結果を受け取ります。コントローラーは、許可されたツールを実行します。モデルは、ワーカーに直接接続したり、モデルAPIキーを取得したりすることはありません。ブラウザが会話を表示し、コントローラーを制御します。

## 第一原則

まずは、特定のマシンに対して、限定的な読み取り専用のリクエストを実行します。変更を行う前には、ツールの出力結果を確認する必要があります。ツールが正常に動作している場合でも、モデルが正しくない可能性があります。モデルの認証情報、チャットの保存場所、マシンのアクセス権、ツールの承認などは、別々の問題です。一方を変更しても、他方が自動的に変更されるわけではありません。特に、公開されているチャットエンドポイントは、遠隔操作のためのコントロールプレーンとして保護されるべきです。

外部のMCPクライアントパスについては、[クライアントの接続方法](../clients/connectivity.md)を参照してください。基盤となるツールの引数については、[ツールのリファレンス](../reference/tools.md)を参照してください。
