# Goal、定时会话与长任务

## 选择合适的机制

| 机制 | 用途 |
|---|---|
| 普通聊天推理 | 响应当前提示词，包括工具调用 |
| Chat Goal | 在模型轮次之间继续执行活跃的逻辑会话计划 |
| 定时会话 | 按周期使用已保存提示词启动智能体 |
| 持久 Job 或终端 | 独立于单次模型请求运行命令 |
| 子智能体 | 将明确任务委派至另一个智能体线程 |

定时会话不是持久 Shell Job。Logical Session 也不是聊天会话或操作系统进程。取消其中一项不一定会停止其工具启动的所有任务。

## Chat Goal

对于长任务，要求智能体明确目标，并使用逻辑会话工具维护计划。计划记录步骤及其状态。聊天运行时可以在模型轮次结束时继续活跃计划，无需等待新用户消息或外部 MCP Live Workspace 的空闲计时器。

检查计划和进展，通过可用的 Goal 控件暂停、恢复或取消。续跑需要活跃计划及符合条件的运行，不应继续已完成、阻塞或取消的计划。连续收到无进展的相同回复时会暂停（当前为三个未变化的边界），以避免无限循环。恢复前先解决实际阻塞。

明确完成标准。例如：检查仓库、实现修复、运行相关测试并报告失败。要求智能体记录具体 commit ID 和测试结果，而非仅凭计划状态宣告成功。

外部 MCP 客户端 Goal 机制不同，Logical Session 和 Live Workspace 交接参见[人机界面](../guides/human-interface.md)。

## 创建定时会话

![含已禁用示例任务的定时会话侧栏](../assets/chat/scheduled-chats.png)

打开定时会话管理，创建包含描述性名称、已保存智能体、提示词、时区和周期的任务。选择目标会话，新建会话时可选项目，保存并启用。正式使用前，利用手动运行控件验证配置。

周期支持每小时、每天、工作日、每周、五字段 cron 及连续执行。连续执行按设置的延迟启动后续轮次；零延迟可能持续占用模型与机器资源。普通周期任务最短间隔为五分钟。使用明确的 IANA 时区，如 `Asia/Shanghai` 或 `UTC`，保存后检查下一次运行时间。

工作日 09:00 的 cron 示例：

```text
0 9 * * 1-5
```

这使用指定时区，而不一定是 Controller 系统时区。对于实行夏令时的时区，应注意切换日期。

## 会话目标

- **每次新建会话:** 每次运行独立新建，适用于独立报告。
- **复用同一会话:** 首次运行创建，后续复用，适用于持续监控。
- **指定已有会话:** 选择接收定时消息的现有会话。

复用或已有会话会逐渐增长，并可能触发上下文压缩。不需要历史时可使用独立会话。定时执行要求所选智能体及模型渠道仍然存在且可用。

## 无人值守权限

定时执行由 Controller 管理，保存授权 Scope 名称，而非浏览器登录 Token。必要时保存或手动运行任务完成授权。指定智能体的机器权限生效，普通项目/聊天机器覆盖不是定时任务机器策略。Controller 限制、保存的授权、工具能力和审批仍然有效。

对于需要认证的外部 MCP 服务器，交互式登录不自动意味着具备可续期的无人值守授权。如果定时任务界面提示重新认证或需要配置无人值守访问，启用任务前处理对应服务器凭证，或移除该依赖。不要使用浏览器 Token 替代授权。

使用只读智能体进行监控，明确允许的目标、输出和禁止操作。如果定时任务需要人工回答或审批，检查待处理交互；无人值守不等于无限制访问。监控提示词示例：

```text
检查指定训练任务及其日志。
报告当前步数、loss、吞吐率、ETA 和新增错误。
不要修改文件、重启任务或启动新工作。
数据不可用时，报告具体原因。
```

## 生命周期与恢复

Controller 持久化定时任务与执行状态，并以事务认领每次运行，避免重复启动。浏览器不必保持打开。不要假定遗漏的周期都会补跑，也不要假定所有外部任务都能跨 Controller 重启继续。停机后检查上次运行、下次运行、正在执行的任务及相关会话。

禁用定时任务可阻止后续自动运行。正在运行的轮次应单独检查；停止未来调度不保证取消正在运行的推理或 Shell Job。移除不再需要的任务，并撤销多余智能体权限。

WebUI 智能体创建的 tracked Job 或终端可以在正常模型响应完成后继续运行；Controller 重启本身也不一定终止它。显式中止、机器权限丢失或授权过期可能触发智能体所属任务的取消。如果 Worker 离线，取消可能保持待处理，直到能够送达。确认执行已经停止前，应直接检查 Job 或终端状态。通过受保护的 WebUI 工具路径，智能体只能向本会话所属的 Job/Shell 发送操作或停止它们。外部 MCP 客户端保留原生语义。

智能体后台工具与子智能体任务具有各自生命周期。即使执行完成，结果也可能仍在等待投递；检查会话后台任务面板，获取结果或等待已配置的唤醒机制恢复父智能体。不要仅因结果尚未显示就启动重复任务。

需要跨单次工具请求执行的命令，应使用 LSM tracked Job 或持久终端。将输出保存到日志文件，记录 Job 标识，检查实际进展。参见[使用模式](../guides/usage-patterns.md)。
