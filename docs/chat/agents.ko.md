# Agents와 Skills

## 언제 Agent를 생성해야 하는가?

직접적인 모델 채팅은 단일한 질문이나 작업을 처리하는 데 유용합니다. 에이전트는 저장된 설정으로서, 반복적으로 선택될 수 있으며, 스케줄된 채팅에서 사용되거나 다른 에이전트에게 위임될 수도 있습니다. 서로 다른 에이전트들은 각자 다른 채널, 모델, 지침, 접근 정책을 사용할 수 있습니다. 하지만 모든 에이전트는 같은 컨트롤러를 공유하며, 반드시 같은 메모리 범위나 도구를 사용하는 것은 아닙니다.

## Agent를 설정하기

WebUI를 통해 Agent 관리를 열고, Agent를 생성합니다. 식별 가능한 이름을 지정하고, 해당 모델을 선택합니다. 작업을 설명하는 지침, 원하는 출력 결과, 제약 조건, 검증 요구 사항 등을 기록합니다. 필요한 기능들을 설정한 후, 저장하고 새로운 대화를 시작합니다.

지침, 도구, 승인 및 스킬 설정이 포함된 에이전트 빌더입니다. ![Agent Builder with instructions, tools, approval and Skill settings](../assets/chat/agent-builder.png)

예를 들어, 리포지토리 검토자는 다음과 같은 지침을 가질 수 있습니다:

```text
현재의 메인 브랜치와 비교하여 변경 사항을 확인하세요.
결론을 내리기 전에 저장소와 테스트 결과를 꼼꼼히 검토하세요.
파일을 수정하거나 커밋을 푸시하거나, 어떤 작업도 수행하지 마세요.
구체적인 발견 사항을 보고할 때는 경로와 관련 증거를 함께 제공해야 합니다.
```

지침은 행동을 조절하는 데 유용하지만, 권한 설정의 기준이 되지는 않습니다. 머신에 대한 접근권을 읽기 전용으로 설정하고, 검토자가 아무것도 변경하지 않아야 하는 경우에는 불필요한 외부 MCP 기능을 사용하지 마세요. 자세한 내용은 [도구 및 권한](permissions.md)을 참조하세요.

각각의 역할에 대해 별도의 에이전트를 사용하는 것이 좋습니다. 예를 들어, 코드 리뷰, 구현 및 운영과 같은 역할들에 대해서 말입니다. 각 에이전트에게는 가능한 한 최소한의 접근 권한을 주고, 그 역할에 적합한 모델을 사용해야 합니다. 만약 어떤 에이전트가 작동하지 않는다면, 해당 에이전트가 참조하는 채널과 모델을 확인한 후에야 관련 없는 설정을 변경할 수 있습니다.

## Skills

스킬 패키지는 재사용할 수 있는 지침과 관련 파일들을 포함합니다. 일반적으로 이러한 파일들은 `SKILL.md`라는 파일 형태로 저장됩니다. 스킬들은 웹 UI를 통해 관리되며, 필요한 경우 해당 스킬들이 활성화되어 에이전트나 채팅 시스템에서 사용될 수 있도록 합니다. 모델은 필요할 때 스킬에 포함된 내용을 자동으로 감지하고 로드할 수 있습니다. 스킬은 워크플로우를 설명하거나 예시를 제공할 수도 있으며, 스크립트를 포함할 수도 있습니다. 하지만 스킬은 자동으로 스크립트를 실행하거나 추가적인 권한을 부여하지는 않습니다.

수입된 스킬들을 활성화하기 전에 반드시 검토해야 합니다. 해당 스킬들의 설명과 파일들도 다른 제3자 코드나 프롬프트와 마찬가지로 처리해야 합니다. 스킬의 이름과 설명은 모델이 쉽게 인식할 수 있도록 충분히 구체적이어야 합니다. 또한, 큰 참조들은 별도로 관리하고, 작은 단위로 구성된 작업 흐름을 선호합니다. 컨트롤러 측의 레지스트리와 도구 호출에 대한 내용은 [Skills](../guides/skills.md)에서 설명되어 있습니다.

자동으로 처리되는 기술과 메모리 내용은 대화를 진행할 때 매 턴마다 시스템 프롬프트를 다시 입력하는 것을 방지하기 위해 저장됩니다. 명시적인 기술 설정의 변경 사항도 즉시 적용될 수 있습니다. 새로 편집된 자동 처리 내용을 테스트할 때는 새로운 대화를 사용해야 합니다. 의도적으로 로드된 기술은 초기 자동 처리 결과와는 다릅니다.

## 위임 및 하위 대리인들

Agents는 그 기능이 가능할 경우, 제한된 작업을 하위 에이전트에게 위임할 수 있습니다. 하위 에이전트는 설정된 Agent를 사용하면서도, 자신의 대화형 실행 스레드를 유지할 수 있습니다. 부모 에이전트는 작업을 조정하고, 하위 에이전트의 결과를 읽어들인 후, 저장된 하위 에이전트의 스레드를 계속 실행할 수 있습니다. 하위 에이전트의 활동은 부모 에이전트가 확인할 수 있으며, 이 정보는 독립적으로 편집할 수 있는 채팅 기능과는 별개입니다.

독립적인 검토나, 별도의 파일 영역 관리, 또는 서로 다른 가설에 대한 조사와 같은 분리된 작업들은 위임을 통해 처리해야 합니다. 아이에게 구체적인 목표와 범위, 그리고 기대되는 결과를 명확히 설명해 주세요. 동시에 같은 파일에 데이터를 쓰는 것은 피해야 합니다. 단, 작업이 명확하게 조율된 경우에는 예외로 합니다.

위임된 작업들은 반드시 부모가 허용한 범위 내에서만 수행되어야 합니다. 부모가 사용할 수 없는 머신이나 MCP 서비스에 접근하는 것은 허용되지 않습니다. 자식 작업의 정책은 부모의 정책을 약화시킬 수 없습니다. 자식 작업들은 모델 토큰과 시간을 독립적으로 소비할 수 있으므로, 비용과 진행 상황을 평가할 때 그들의 활동과 결과를 반드시 확인해야 합니다.

## 도구들, 행동들, 그리고 유물들

Agent Builder는 사용 가능한 도구와 고급 설정을 제공합니다. 필요한 기능만 선택하세요. OpenAPI 스키마에 의해 정의된 HTTP 액션의 경우, 해당 엔드포인트, 인증 요구 사항, 허용되는 작업들을 반드시 확인해야 합니다. 각 액션은 자체적인 인증 방식을 가질 수 있으며, 머신 권한은 제3자 API 자격 증명을 승인하거나 거부하지 않습니다. 원격 변경이 완료된 후에는 해당 액션의 응답 내용을 반드시 확인해야 합니다.

생성된 UI 콘텐츠의 경우, [Conversations and projects](conversations.md)에 설명된 대로 아티팩트 렌더링을 구성해야 합니다. 생성된 코드는 Controller의 신뢰할 수 있는 확장 기능이 아닙니다.

## 실용적인 Agent 템플릿들

- **읽기 전용 조사관:** 로그와 원본 자료를 검토하고, 증거들을 비교합니다. 원인을 분석하여 보고서를 작성합니다. 어떠한 변경도 하지 않습니다.
- **Agent의 구현:** 리포지토리를 편집하고, 관련된 테스트를 실행하며, 발생한 차이점과 해결되지 않은 문제들을 보고합니다. 필요한 경우, 민감한 작업을 수행하기 전에 승인을 받아야 합니다.
- **모니터링 에이전트:** 지정된 머신들을 점검하여 상태, 오류, 그리고 측정된 진행 상황을 보고합니다. 명시적으로 허가받지 않는 한, 작업을 다시 시작하지 않습니다.
- **연구 요원:** 네트워크 검색 기능을 활성화하고, 원본 문서를 인용할 수 있도록 합니다. 또한, 증거와 추론 결과를 구분할 수 있으며, 필요한 경우에만 기계 도구를 사용합니다.

이 템플릿들은 단순한 지침일 뿐, 내장된 설정값은 아닙니다. 각 에이전트의 실제 권한과 기능을 조정하여, 그 에이전트가 맡아야 할 역할에 맞게 설정해야 합니다.
