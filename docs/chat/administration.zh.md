# 管理与故障排查

## 部署架构

WebUI 前端由 Python Controller 提供，与 REST 和 MCP 端点共享同源服务。默认状态后端是 SQLite。发布的二进制与 wheel 内置编译后的前端资源；源码构建需要 JavaScript 工具链，运行已安装的 Controller 不需要。Node.js、MongoDB、Meilisearch 和独立 LibreChat 后端不再是运行时依赖。

参见[快速入门](../getting-started/quickstart.md)及[配置参考](../reference/configuration.md)。源码构建参见[WebUI 构建说明](https://github.com/fwerkor/local-shell-mcp/blob/main/ui/workspace/README.md)。

## 保护部署

使用可信 HTTPS 反向代理或隧道、认证与强凭证。将 Controller 置于适当的容器或虚拟机隔离边界，限制入站访问并保护出站凭证。不要将未认证的执行端点暴露到公网。

代理应支持流式响应，避免缓存到生成结束才发送；需要 WebSocket 的界面应允许升级。为较长模型/工具请求设置合适的读取和空闲超时，允许预期附件大小。配置的公开 URL 应与浏览器源地址及 OAuth 回调一致。不要通过全局禁用证书验证来修复 TLS 问题。

模型请求由 Controller 发出，模型可见消息、附件及工具结果可能发送给所选上游 API。处理机密内容前评估提供方数据处理条款。同时保护外部 MCP 凭证与 Worker 邀请令牌。

## 状态、备份与升级

默认状态目录为工作区下的 `.local-shell-mcp`，可通过 `LOCAL_SHELL_MCP_STATE_DIR` 修改。共享数据库为 `lsm.sqlite3`。聊天、项目、设置、智能体、记忆、定时任务和执行状态保存于服务端；附件、工作区文件及其他产物可能位于数据库外。

备份完整状态目录、目录外的配置状态、部署环境/凭证及相关工作区文件。将备份视为敏感数据。仅备份数据库可能遗漏附件或配置。使用已停止写入的 Controller 或一致性 SQLite 备份机制；只复制运行中 SQLite 主数据库文件可能遗漏 WAL 中已提交数据。应在隔离测试部署中验证恢复。

升级前记录当前版本、运行路径、配置、状态位置及活跃任务。停止或安全排空相关执行，完成一致性备份，升级同一套安装，并验证认证、聊天历史、模型生成、流式响应、Worker 和定时任务。启动时支持旧状态迁移到 SQLite；验证迁移前保留旧文件。不要用空测试数据目录替换生产目录。

如果数据库迁移改变持久化状态，回滚不只是替换二进制。必要时恢复兼容状态，不要让两个独立配置的 Controller 同时使用同一份活动存储。

## 聊天失败诊断

| 现象 | 优先检查 |
|---|---|
| 无法加载 UI | Controller 进程、前端资源、URL、代理和认证 |
| 模型缺失 | 渠道配置、自动发现、模型 ID、账户授权 |
| 提供方返回 401/403 | API Key/账户、提供方权限、所选渠道和协议 |
| HTTP 429 | 上游速率或额度限制、并发请求、账户/套餐状态 |
| HTTP 400/413/422 | 请求兼容性、输入与窗口大小、附件限制、模型参数 |
| HTTP 5xx 或超时 | 提供方健康状况、网络、推理服务容量、代理超时 |
| 流式输出停止 | 重连或刷新，查看推理状态和详细错误 |
| 工具不可用 | 功能开关、智能体能力、机器 ACL、OAuth Scope、Controller 开关 |
| Worker 离线 | Worker 注册、出站连接、心跳及 Controller 日志 |
| 等待审批/回答 | 打开会话并检查所请求操作 |
| 定时任务不执行 | 启用状态、时区、智能体/渠道、目标、授权、上次运行 |

不要假定所有 HTTP 错误来自同一服务：区分 LSM 登录失败、上游模型 API 错误、外部 MCP 错误和 Worker 传输错误。查看详细错误和相应 Controller 日志；分享前删除 Key、Bearer Token 和回调 URL。

## 提供方重试与恢复

模型响应开始前，临时连接错误和部分 HTTP 错误（408、429、500、502、503、504）可以进行有界退避重试。当前普通重试延迟为 1、2、4、8、16、30、30、30 秒（初始请求后最多八次重试）。HTTP Retry-After 可以将延迟延长至 120 秒；部分流式错误加入随机抖动。重试预算针对单次模型请求，并非整个会话的累计计数。上下文压缩有独立的恢复路径。额度耗尽导致的限流可能持续到提供方补充额度。自动重试不能保证最终成功，也不会让订阅获得无限额度。

流式响应中断与首个响应事件之前的失败不同。不要依赖自动重放已经部分执行的工具序列。重试前检查保存的历史和外部状态。任务仍在运行时应重连，避免重复启动。如果已经失败，按需使用聊天恢复/重试控件；原会话无法继续时，也可在新会话中明确交接任务。

上下文压缩失败应与普通推理错误分别调查。检查实际窗口长度、模型兼容性、超大工具结果及剩余额度。参见[记忆与上下文](context.md)。

## Bug 报告内容

提供 LSM 版本/commit、安装方式、操作系统、模型协议、脱敏端点类型、模型 ID、时间、复现步骤、相关会话/运行状态和脱敏后的详细错误。远程问题另外提供 Worker 版本、机器名和 heartbeat/poll 状态。尽量提供最小复现，不要发送 API Key、OAuth Token、私密提示词或无关个人信息。
