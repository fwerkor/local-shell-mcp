# Каналы и модели

## Настройка канала

Откройте меню выбора модели в Chat и перейдите на страницу управления каналами. Выберите опцию **Добавить канал**, выберите тип соединения, введите необходимую информацию и сохраните изменения. Затем выберите подходящую модель для нового чата. Для создания персонального агента выберите нужный канал и модель в разделе настроек агента.

Каналы являются собственностью контроллера, а не личными настройками пользователей. В случае авторизованной работы управление каналами требует использования полномочий `admin:config`. Администратор может настроить общие каналы без необходимости распространения API-ключей среди пользователей.

![Добавление модели в конфигурацию канала](../assets/chat/channel-settings.png)

У обычного канала API есть имя, протокол обмена данными, основная URL-адрес, учетные данные и идентификаторы моделей. Не используйте пароль от своего аккаунта LSM – используйте ключ API, выданный для выбранного конечного пункта обмена данными. LSM отправляет запросы через Контроллер; URL-адрес, работающий на вашем ноутбуке, может не работать в Контроллере.

| Протокол | Пример основного URL-адреса API | Использование |
|---|---|---|
| OpenAI Chat Completions | `https://api.openai.com/v1` | Гейтвайзы совместимые с OpenAI и локальные серверы инферирования |
| OpenAI Responses | `https://api.openai.com/v1` | Гейтвайз, предоставляющий доступ к API для получения ответов |
| Антропный уроженец | `https://api.anthropic.com/v1` | API-интерфейсы, совместимые с антропными сообщениями |
| Родной Google Gemini | `https://generativelanguage.googleapis.com/v1beta` | API-интерфейсы, совместимые с функцией генерации контента в Gemini |

Необходимо использовать базовый URL, предусмотренный сервисом, а не полный адрес запроса, например адрес в формате `/chat/completions`. Сервисы, утверждающие свою совместимость с OpenAI, могут поддерживать только функцию генерации сообщений, но не возможности получения ответов, использования инструментов, мультимодальных входных данных или решающих процессов. Необходимо выбрать протокол, который действительно поддерживается сервисом. Примеры URL-адресов являются лишь примерами; это не гарантирует бесплатный доступ или наличие сервиса.

## Локальные и пользовательские конечные точки

Для сервера, совместимого с OpenAI, который работает на самом контроллере, основная адресная строка может быть следующей: `http://127.0.0.1:8080/v1`. Когда сервер работает в Docker-контейнере, под „loopback“ подразумевается именно этот контейнер, а не физический хост. Необходимо использовать адрес, доступный из сетевого пространства контроллера. Одного лишь регистрации удаленного рабочего процесса недостаточно для того, чтобы API для вычислений был доступен.

Модель проверки URL требует использования протокола HTTPS, за исключением случаев, когда речь идет о HTTP-точках на локальных хостах (`localhost`, `127.0.0.1`, `::1`). HTTP-точка, расположенная на локальной сети или внутри Docker-сервиса, должна быть доступна через HTTPS-шлюз. Использование частных endpoints для обмена данными невозможно. В основных URL-адресах не должны содержаться какие-либо учетные данные, фрагменты данных или строки запросов.

Используйте протокол TLS для обслуживания удаленных конечных точек. Ограничивайте доступ только к защищенным частным шлюзам. Проверяйте идентификаторы моделей перед использованием их в сервере инсайнинга. Никогда не размещайте ключи API в форматах, таких как скриншоты, строки запросов или опубликованная конфигурация. При редактировании существующих каналов оставляйте ключ API пустым, чтобы сохранить его в файле. Используйте безключевой подход только в тех случаях, когда сервис это разрешает.

## Предустановленные параметры окружения

Встроенный профиль OpenAI можно настроить перед запуском с помощью переменных `LOCAL_SHELL_MCP_MODEL_BASE_URL` (или `OPENAI_BASE_URL`), `LOCAL_SHELL_MCP_MODEL` и `LOCAL_SHELL_MCP_MODEL_API_KEY` (или `OPENAI_API_KEY`). Встроенные профили Anthropic и Google могут использовать ключи `ANTHROPIC_API_KEY` и `GOOGLE_KEY` / `GOOGLE_API_KEY`. Сохраненные встроенные профили имеют приоритет перед параметрами окружения. Используйте назначенные каналы для обслуживания нескольких независимых конечных точек. Предустановленные параметры окружения не являются альтернативой защите секретов сервиса.

## Авторизация аккаунта ChatGPT

Канал account/Codex использует процесс авторизации, связанный с аккаунтом ChatGPT, а не обычный ключ API. Авторизацию можно выполнить через меню управления каналами или на официальной странице авторизации. В локальном развертывании процесс авторизации может происходить автоматически. Если браузер не может связаться с сервером, скопируйте полный адрес URL из адресной строки и введите его в диалоговое окно авторизации. Ожидается, что возникнут проблемы с соединением на этом сервере.

Относитесь к URL обратного вызова как к учётным данным: никогда не отправляйте его в чате и не публикуйте. Controller хранит авторизацию на сервере и по возможности обновляет учётные данные. Повторно авторизуйте аккаунт при истечении срока действия или отзыве доступа. Доступные модели, ограничения тарифа и допустимое использование определяет вышестоящая служба аккаунта; LSM не предоставляет дополнительную квоту подписки.

## Определение моделей и ограничения контекста

Установите функцию автоматического обнаружения для запроса информации о моделях от поставщика. Контроллер обновляет эту информацию периодически (в данный момент каждые десять минут); также возможен ручной обновление данных. Если процесс обнаружения не удается, предыдущие данные о моделях сохраняются. Если у поставщика отсутствует соответствующий endpoints для передачи информации о моделях, отключите функцию автоматического обнаружения и введите идентификаторы моделей вручную, по одному на строку.

Необходимо указать окно контекста для каждой модели, когда это известно. Явное значение для каждой модели может заменить метаданные, которые были обнаружены, или заполнить отсутствующие значения. Экспеллер поддерживает использование от 1 до 2,000,000 токенов. Это конфигурационный диапазон, а не гарантия того, что поставщик поддерживает такую производительность. Используйте оптимальный лимит для своей развертывания, учитывая настройки сервера и ограничения самой модели.

## Сэмплирование, рассуждения и использование

Предустановленные параметры канала/модели определяют параметры запросов, поддерживаемые выбранным поставщиком услуг. Компонент обработки чата может предоставлять информацию о рассуждениях, если таковая имеется. Различные протоколы реализуют сэмплирование и рассуждения по-разному. Некоторые функции могут не поддерживаться определенной моделью. Начните с предустановленных значений поставщика услуг, затем изменяйте одно значение за раз.

ЛСМ может запросить точные данные о количестве использованных токенов для передачи данных. Если провайдер отказывается принимать такие данные, LSM может использовать альтернативный вариант обработки данных. Эндпоинт, который не возвращает информацию о количестве использованных ресурсов, не может предоставить точную информацию о расходе ресурсов или статистику использования данных в кэше. См. раздел [Память и контекст](context.md) для понимания различий между совокупным объемом использования ресурсов и текущим объемом их доступности.

## Изменение и удаление каналов

Разговор сохраняет свой выбранный модель/Агент и историю его действий. Модель следует изменять только в случае необходимости смены конечных точек или при наличии проблем с сервисом. Изменение названия используемого канала ограничено, чтобы не создавать лишних ссылок. Удаление используемого канала требует дополнительной подтверждения: история сохраняется, но Агенты и чаты, которые ссылаются на удаленный канал, должны выбрать другой вариант для использования.

Настройки каналов находятся на стороне сервера, а не в браузере. Ключевые данные для авторизации не возвращаются в виде стандартных ответов от каталога каналов. Необходимо защищать директорию состояния контроллера и резервные копии данных, так как они содержат ключевые данные для авторизации.

## Перечень необходимых для соединения элементов

1. Убедитесь, что контроллер может связаться с хостом, предоставляющим API-сервисы, и что протокол TLS используется для обеспечения безопасности соединения.
2. Убедитесь в правильности указанного основного пути, протокола, данных для авторизации, а также точного идентификатора модели.
3. Пересмотрите имеющиеся модели или введите один из известных моделей вручную.
4. Сначала отправьте короткий текстовый запрос. Затем протестируйте работу небольшого инструмента.
5. Убедитесь в деталях ошибки, связанных с состоянием HTTP-сети, таймаутом или неподдерживаемыми параметрами. Не повторяйте попытки, если учетные данные являются недействительными.

См. раздел [Управление и решение проблем](administration.md) для информации о способах работы с ограничениями скорости передачи данных, возникновении перебоев в потоке данных и ошибках авторизации.
