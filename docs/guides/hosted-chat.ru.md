# Хостинг-чат (необязательно)

Hosted Chat — это автономный чат BYOK и клиент MCP Apps, интегрированный в человеческий интерфейс LSM. Это **не** режим логического сеанса: диалоги имеют независимые идентификаторы и при необходимости могут присоединять существующий логический сеанс LSM. ChatGPT и другие внешние клиенты продолжают работать с теми же сеансами и инструментами LSM.

## Включить

По умолчанию размещенный чат отключен. Набор:

```env
LOCAL_SHELL_MCP_HOSTED_CHAT_ENABLED=true
```

Перезапустите контроллер и откройте **Размещенный чат** сразу под переключателем Веб-интерфейс/TUI. Эта функция также имеет доступ к мобильной верхней панели. Хост чата использует существующие идентификаторы и области LSM OAuth. Тот же контроллер управляет сервером MCP, используемым в инструментальном цикле модели; Рабочие не могут инициировать выполнение.

## Профили моделей

Выберите **Профили модели**, чтобы создать/изменить профиль с именем, базовым URL-адресом HTTPS OpenAI-совместимого API, идентификатором модели и дополнительным ключом API. Несколько профилей могут сосуществовать, а разговоры могут переключать модели.

Профили, разговоры, полная история сообщений и результаты вызовов инструментов **сохраняются на сервере** через настроенную серверную часть состояния LSM. Их область действия привязана к аутентифицированному субъекту. Ключ API шифруется с помощью AES-GCM и никогда не возвращается из конечных точек списка профилей или сведений о профиле. Он не сохраняется в хранилище браузера, не отправляется в модель в виде запроса и не включается в журналы аудита. Хост чата передает его только API выбранной модели.

При первом развертывании с использованием файла создается `hosted-chat-encryption-key` в каталоге состояния с режимом 0600. **Создайте резервную копию этого файла вместе с данными состояния. Без него сохраненные ключи API невозможно расшифровать.** Если контроллер использует Redis, несколько реплик или другой сервер, не являющийся файловым, настройте стабильный общий 32-байтовый ключ URL-safe-base64:

```env
LOCAL_SHELL_MCP_HOSTED_CHAT_ENCRYPTION_KEY=<base64url-encoded 32 random bytes>
```

Не меняйте этот параметр без переноса зашифрованных профилей. Не используйте хранилище состояний в памяти, когда требуются длительные диалоги.

По умолчанию принимаются только конечные точки модели HTTPS с именами хостов DNS; локальные/частные конечные точки и HTTP запрещены, чтобы снизить риск подделки запросов на стороне сервера. Администраторы, намеренно размещающие доверенный шлюз частной модели, могут выбрать следующее:

```env
LOCAL_SHELL_MCP_HOSTED_CHAT_ALLOW_PRIVATE_ENDPOINTS=true
```

Не включайте это на ненадежном многопользовательском контроллере, если пользователям не разрешено обращаться к внутренним службам.

## Разговоры и приложения MCP

Создайте разговор, используя сохраненный профиль модели. Каждый отправленный ход становится фоновой задачей, принадлежащей серверу; закрытие браузера не отменяет задачу. Завершенный текст и вызовы инструментов постоянно проверяются между этапами модели/инструмента. Остановитесь явно, чтобы прервать. При перезапуске контроллера прерванные прогоны помечаются как таковые и могут быть продолжены в новом ходе, но **вызовы инструментов с неизвестным результатом никогда не воспроизводятся автоматически**.

Вся история сообщений разговора сохраняется в хранилище. В модель сразу отправляется только ограниченное недавнее окно для управления размером контекста. Вызовы инструментов отправляются через аутентифицированную конечную точку MCP LSM, сохраняя все обычные разрешения инструментов и поведение аудита/предпечатной проверки.

Архивация убирает диалог из обычного списка и сохраняет его в `.json.zst` с существующим кодеком zstd из Audit. Архивы не попадают в обычный поисковый индекс. В **Archived conversations** доступен поиск по заголовку, просмотр без изменений, восстановление и окончательное удаление. Новая копия записывается до удаления старой, чтобы избежать потери данных.

### Длинные диалоги и сжатие контекста

Полная история сообщений и инструментов остаётся на сервере. Окно контекста задаётся в профиле модели: по умолчанию **32 768 токенов**, допустимо от 8 192 до 1 000 000. Консервативная оценка по UTF-8 включает описания инструментов. При достижении примерно **80%** то же модельное подключение суммирует завершённые ранние реплики, сохраняя цели, ограничения, решения, пути файлов, результаты и незавершённые задачи. Сводка хранится отдельно; модели отправляются сводка и последние исходные сообщения.

Лимит проверяется и после вызовов инструментов. Кнопка **Compact** запускает процесс вручную, кроме времени выполнения активного запроса. При ошибке прежняя сводка и полная история не меняются. Число токенов приблизительное; слишком длинный текущий запрос отклоняется без скрытой обрезки.

Откройте **Live Workspace**, чтобы отобразить существующий ресурс LSM `workspace_open` MCP Apps во встроенном представлении. Хост использует мост `@modelcontextprotocol/ext-apps` для жизненного цикла приложения, обновления учетных данных, вызовов инструментов и действий между человеком и агентом. Никакого второго файлового менеджера, терминала, пользовательского интерфейса аудита или заданий не реализовано.

Дополнительный прикрепленный код `session_id` позволяет размещенному чату использовать и отображать существующий логический сеанс; он не переклассифицирует сеанс и не передает право собственности на него размещенному чату. Идентификаторы разговоров чата и идентификаторы логического сеанса являются отдельными.

## Границы

- В запросах моделей используются OpenAI-совместимые дополнения чата с вызовом инструментов; для других протоколов провайдера требуется адаптер.
- Пошаговая защита ограничивает количество итераций модели и вызовов инструментов. Более длительные задачи можно продолжить на новом ходу, используя длительную историю.
- Удаление разговора в чате является явным. Автоматическое удаление истории не производится.
- Контроллер должен быть доступен по сети для собственного клиента MCP, а браузер должен быть авторизован для API LSM Live Workspace.
