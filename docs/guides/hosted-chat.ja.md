# ホスト型チャット (オプション)

Hosted Chat は、LSM のヒューマン インターフェイスに統合された自己ホスト型の BYOK チャットおよび MCP アプリ クライアントです。これは論理セッション モードではありません。会話には独立した ID があり、オプションで既存の LSM 論理セッションを接続できます。 ChatGPT および他の外部クライアントは、同じ LSM セッションおよびツールを引き続き使用します。

## 有効にする

ホスト型チャットはデフォルトでは無効になっています。設定:

```env
LOCAL_SHELL_MCP_HOSTED_CHAT_ENABLED=true
```

コントローラーを再起動し、Web UI / TUI セレクターのすぐ下にある **ホストされたチャット** を開きます。この機能には、モバイル トップバー エントリもあります。チャット ホストは、既存の LSM OAuth ID とスコープを使用します。同じコントローラが、モデルのツール ループで使用される MCP サーバーを操作します。ワーカーは実行を開始できません。

## モデルプロファイル

[**モデル プロファイル**] を選択して、名前、HTTPS OpenAI 互換 API ベース URL、モデル ID、およびオプションの API キーを使用してプロファイルを作成/編集します。複数のプロファイルを共存させることができ、会話でモデルを切り替えることができます。

プロファイル、会話、完全なメッセージ履歴、およびツール呼び出しの結果は、構成された LSM 状態バックエンドを介して **サーバーに保存**されます。それらのスコープは、認証されたプリンシパルに関連付けられます。 API キーは AES-GCM で暗号化され、profile-list エンドポイントや profile-detail エンドポイントから返されることはありません。これは、ブラウザーのストレージに保存されたり、プロンプトとしてモデルに送信されたり、監査ログに含まれたりすることはありません。チャット ホストは、選択したモデル API にのみそれを渡します。

最初のファイルバックアップ展開では、状態ディレクトリにモード 0600 で `hosted-chat-encryption-key` が作成されます。 **このファイルを状態データと一緒にバックアップします。これがないと、保存された API キーを復号化できません。** コントローラーが Redis、複数のレプリカ、または別の非ファイル状態バックエンドを使用する場合は、安定した共有 32 バイト URL-safe-base64 キーを構成します。

```env
LOCAL_SHELL_MCP_HOSTED_CHAT_ENCRYPTION_KEY=<base64url-encoded 32 random bytes>
```

暗号化されたプロファイルを移行せずに、この設定を変更しないでください。永続的な会話が必要な場合は、メモリ内状態ストレージを使用しないでください。

デフォルトでは、DNS ホスト名を持つ HTTPS モデルのエンドポイントのみが受け入れられます。ローカル/プライベート エンドポイントと HTTP は、サーバー側のリクエスト フォージェリのリスクを軽減するために拒否されます。信頼されたプライベート モデル ゲートウェイを意図的にホストしている管理者は、次のことをオプトインできます。

```env
LOCAL_SHELL_MCP_HOSTED_CHAT_ALLOW_PRIVATE_ENDPOINTS=true
```

ユーザーが内部サービスへの接続を許可されていない限り、信頼できないマルチユーザー コントローラではこれを有効にしないでください。

## 会話と MCP アプリ

保存されたモデル プロファイルを使用して会話を作成します。提出された各ターンはサーバー所有のバックグラウンド タスクになります。ブラウザを閉じてもタスクはキャンセルされません。完了したテキストとツールの呼び出しは、モデル/ツールのステップ間で永続的にチェックポイントされます。中断するには明示的に停止します。コントローラーの再起動時に、中断された実行はそのようにマークされ、新しいターンで続行できますが、**結果が不明なツール呼び出しは自動的に再実行されることはありません**。

会話のメッセージ履歴全体がストレージに保持されます。コンテキスト サイズを制御するために、制限された最近のウィンドウのみが一度にモデルに送信されます。ツール呼び出しは、LSM の認証された MCP エンドポイントを介して送信され、すべての通常のツール権限と監査/プリフライト動作が維持されます。

アーカイブすると会話は通常の一覧から除かれ、Audit で使用中の zstd を再利用して `.json.zst` 形式で保存されます。通常の検索インデックスには含まれません。**Archived conversations** ではタイトルで探し、読み取り専用で確認し、復元や完全削除ができます。保存後に元のデータを消すため、障害時の損失を防ぎます。

### 長い会話とコンテキストの圧縮

元のメッセージとツール実行履歴はすべてサーバーに残ります。モデルごとのコンテキスト窓は初期値 **32,768 トークン**、設定範囲は 8,192～1,000,000 です。UTF-8 に基づく保守的な推定にはツール定義も含まれます。約 **80%** に達すると、同じモデルが完了済みの古い会話を要約します。要約には目的、制約、判断、ファイル、実行結果、未完了作業が含まれ、元の履歴とは別に永続保存されます。モデルには要約と最近の元メッセージを渡します。

ツール実行後にも容量を再評価します。**Compact** で手動実行できますが、処理中のターンでは実行できません。失敗しても元の履歴や要約は変わりません。トークン数は概算で、収まらない現在のターンは黙って切り捨てずエラーにします。

**ライブ ワークスペース** を開き、LSM の既存の `workspace_open` MCP アプリ リソースを埋め込みビュー内にレンダリングします。ホストは、アプリのライフサイクル、認証情報の更新、ツール呼び出し、および人間からエージェントへのアクションに `@modelcontextprotocol/ext-apps` ブリッジを使用します。 2 番目のファイル マネージャー、ターミナル、監査、またはジョブ UI は実装されていません。

オプションの付属の `session_id` を使用すると、ホスト型チャットで既存の論理セッションを使用および表示できます。セッションを再分類したり、ホストされたチャットの所有権を付与したりすることはありません。チャット会話識別子と論理セッション識別子は別のものです。

## 境界線

- モデルリクエストは、ツール呼び出しによる OpenAI 互換のチャットコンプリーションを使用します。他のプロバイダー プロトコルにはアダプターが必要です。
- ターンごとの保護手段により、モデルの反復とツールの呼び出しが制限されます。より長いタスクは、永続的な履歴を使用して新しいターンで継続することができます。
- チャット会話の削除は明示的です。履歴の自動削除は実行されません。
- コントローラーは、独自の MCP クライアントからネットワークに到達可能である必要があり、ブラウザーは LSM ライブ ワークスペース API に対して承認されている必要があります。
